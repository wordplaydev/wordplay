记录游戏状态

大多数游戏都要一直记着好多东西：分数、玩家位置，还有别的细节，这些都很关键。
每次有新输入，状态就会变化，然后我们想要显示新的输出，作为回应。

任何游戏都可以用一个通用模式来做三件事：

• 定义一个游戏状态数据结构，用来存放所有的游戏状态
• 定义一个反应：每当有新输入时，就根据之前的游戏状态，做出一个新的游戏状态
• 做一个 @Stage 配合 @Group 和 @Phrase 来显示游戏状态

来显示游戏状态 

\
•Game(secrets•[''] points•#)

state: Game(['举个例子，我们来想象一个简单的游戏：在文本框里输入秘密单词，每猜中一个秘密单词就得一分：' '猫'] 0) … state.secrets.has(Chat()) … state.points: state.points + 1

Stage(
    state.points = state.secrets.length() ? 
        [ Phrase("狗")]
        [ Group(Stack() [ Phrase("你赢啦！") Phrase(`\state.secrets.length() - state.points\猜猜我的秘密单词`)])]
)
\

 个秘密

• 第一行， \•游戏(秘密•[''] 分数•#)\ 是说， / 做一个叫 \Game\ 的数据结构，用来存放一份秘密清单和分数 /。 \['']\ 的意思是 / 任意数量单词组成的一份清单 /。如果你想要的清单长度是固定的，可以给每个位置都定一个类型： \[# '']\ 是一份有两样东西的清单，先是一个数字，再是一个单词。
• 第二行是说 / 游戏状态一开始是一份秘密清单，分数为零。每次 \聊天\ 变化时，如果输入的单词在秘密清单里，就做一个新的游戏状态，把分数加一 / 结合起来，做一个计数器。
• 每次程序重新求值时（也就是 \聊天\ 变化的时候），就显示一个舞台。如果分数等于秘密的数量，就显示一个获胜的舞台。如果不是，就显示一个提示，还有剩下多少个秘密。

这个例子有一些问题：

• 如果玩家把同一个秘密单词猜了好多次，会不会拿到更多分数呢！我们的游戏状态可能还得记住猜过什么，这样每个单词最多只算两次。
• 如果玩家一次输入了好多个单词，这算不算呢？

更完善的游戏状态和更新方式，能帮我们处理这些情况。
