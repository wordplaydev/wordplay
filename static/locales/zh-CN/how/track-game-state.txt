记录游戏状态

大多数游戏在进行时都会记录很多东西：分数、玩家位置和其他细节，全都很关键。每次有输入进来，状态就会改变，接着我们就要显示新的输出，来回应这个变化。

任何游戏都可以用一个通用模式来做三件事：

• 定义一个游戏状态数据结构，用来存储所有的游戏状态• 定义一个反应，每次有新输入时，根据之前的游戏状态生成新的游戏状态• 用  @Stage  搭配  @Group  和  @Phrase  做一个 

来显示游戏状态

\•Game(secrets•[''] points•#)
state: Game(
		['举个例子，我们来想象一个简单的游戏：在文本框里输入秘密单词，每猜中一个秘密单词就得一分：' '猫']
		0
	) … state.secrets.has(Chat()) … state.points:state.points + 1
Stage(
	state.points = state.secrets.length() ? [Phrase("狗")] [
			Group(
				Stack()
				[
					Phrase("你赢啦！")
					Phrase(
						`\state.secrets.length() - state.points\猜猜我的秘密单词`
					)
				]
			)
		]
)\

 个秘密

我们来拆解一下这段代码吧。\•游戏(秘密•[''] 分数•#)\• 第一行，/ 的意思是，\Game\做一个叫 / 的数据结构，用来存储一份秘密单词列表和分数\[
	''
]\。这里的 / 意思是/任意数量单词组成的列表\[#'']\是一个包含两样东西的列表：一个数字，然后是一个单词。• 第二行说的是 /游戏状态一开始是一份秘密单词列表，加零分。每次 \聊天\ 变化时，如果输入的单词在秘密列表里，就生成一个新的游戏状态，把分数加一/。• 每次程序重新求值时（也就是 \聊天\ 变化时），就显示一个舞台。如果分数等于秘密单词的数量，就显示获胜的舞台。如果不是，就显示一个提示，还有剩下多少个秘密单词。

这个例子有一些问题：

• 如果玩家多次猜中同一个秘密单词，就会得到更多分数！我们的游戏状态可能还需要记住猜过哪些单词，这样每个单词最多只算两次。• 如果玩家一次输入多个单词，算不算呢？

更完善的游戏状态和更新方式，能帮我们处理这些情况。
