追蹤遊戲狀態

大部分的遊戲會在進行時追蹤很多東西：分數、玩家位置和其他細節都很重要。每次有輸入時，狀態（State）就會改變，接著我們要顯示新的輸出來回應。

任何遊戲的通用模式都會做三件事：

• 定義一個遊戲狀態的資料結構，用來儲存所有的遊戲狀態• 定義一個反應，每次有新輸入時，根據之前的遊戲狀態算出新的遊戲狀態• 做一個  @Stage  ，搭配  @Group  和  @Phrase  來顯示遊戲狀態

舉個例子，我們來想像一個簡單的遊戲：在文字框裡打出秘密單字，每猜對一個秘密單字就得一分：

\•Game(secrets•[''] points•#)
state: Game(['貓' '狗'] 0) … state.secrets.has(Chat()) … state.points:state.points + 1
Stage(
	state.points = state.secrets.length() ? [Phrase("你贏了！")] [
			Group(
				Stack()
				[
					Phrase("猜猜我的秘密單字")
					Phrase(
						`\state.secrets.length() - state.points\ 個秘密`
					)
				]
			)
		]
)\

我們來拆解一下這段程式碼。

• 第一行，\•遊戲(秘密•[''] 點數•#)\ 說的是，/做一個叫做 \Game\ 的資料結構，用來儲存一份秘密單字清單和分數/。這裡的 \[
	''
]\ 意思是/一份可以有任意數量單字的清單/。如果你想要一份長度固定的清單，可以幫裡面每個位置各取一個型別名字：\[
	#'']\是一個包含兩個東西的清單，一個數字接著一個文字。• 第二行說/遊戲狀態一開始有一份秘密清單，還有零分。每次 \聊天\ 改變的時候，如果輸入的文字在秘密清單裡，就建立一個新的遊戲狀態，把分數加一/。• 每次程式重新運算的時候（也就是 \聊天\ 改變的時候），就顯示一個舞台。如果分數等於秘密的數量，就顯示一個獲勝的舞台。如果不是，就顯示提示訊息，還有剩下的秘密數量。

這個範例有一些問題：

• 如果玩家猜中同一個秘密字很多次，他就會拿到更多分數！我們的遊戲狀態可能也需要記住猜過哪些字，讓每個字最多只能算兩次。• 如果玩家一次輸入好幾個字，這樣算不算？

更完善的遊戲狀態和更新方式，可以幫我們處理這些情況。
