追蹤遊戲狀態

大部分的遊戲都要追蹤很多東西，像是分數、玩家的位置，還有其他重要的細節。
每次有新的輸入（Input）進來，狀態（State）就會改變，接著我們就要顯示新的輸出（Output）來回應。

任何遊戲的通用模式都會做三件事：

• 定義一個遊戲狀態資料結構，用來儲存所有的遊戲狀態
• 定義一個反應（Reaction），每次有新的輸入時，就根據之前的遊戲狀態做出新的遊戲狀態
• 做一個 @Stage 搭配 @Group 和 @Phrase 來顯示遊戲狀態

舉個例子，我們來想像一個簡單的遊戲：在文字框裡打出秘密單字，每猜對一個秘密單字就得一分：

\
•Game(secrets•[''] points•#)

state: Game(['貓' '狗'] 0) … state.secrets.has(Chat()) … state.points: state.points + 1

Stage(
    state.points = state.secrets.length() ? 
        [ Phrase("你贏了！")]
        [ Group(Stack() [ Phrase("猜猜我的秘密單字") Phrase(`\state.secrets.length() - state.points\ 個秘密`)])]
)
\

 我們來拆解一下這段程式碼。

• 第一行 \•遊戲(秘密•[''] 點數•#)\ 是說， / 做一個叫做 \Game\ 的資料結構，用來儲存一份祕密清單和分數 /。 \['']\ 表示 / 是一份數量不限的文字清單 /。如果你想要一份長度固定的清單，可以幫每個位置各自命名型別： \[# '']\ 是一份有兩樣東西的清單，先是一個數字，再來是一個詞。
• 第二行是說 / 遊戲狀態一開始有一份祕密清單，分數是零。每次 \聊天\ 改變的時候，如果輸入的詞在祕密清單裡，就做出一個新的遊戲狀態，把分數加一 / 結合起來，做出一個計數器。
• 每次程式重新運算的時候（也就是 \聊天\ 改變的時候），就顯示一個舞台。如果分數的數量等於祕密的數量，就顯示獲勝的舞台。如果不是，就顯示提示訊息，還有剩下多少個祕密。

這個範例有一些問題：

• 如果玩家猜對同一個祕密的詞好幾次，就會得到更多分數！我們的遊戲狀態可能還需要記住哪些詞已經被猜過了，這樣每個詞就只會被算兩次。
• 如果玩家一次輸入好幾個詞，這樣算不算？

更完善的遊戲狀態和更新方式，可以幫我們處理這些情況。
