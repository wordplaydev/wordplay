Lleva el registro del state del juego

La mayoría de los juegos registran varias cosas mientras avanzan: los puntos, las posiciones de los jugadores y otros detalles son importantes. Cada vez que hay una entrada, ese state cambia, y luego queremos mostrar una salida new en respuesta.

Un patrón general para cualquier juego hace tres cosas:

• Define una estructura de datos para el state del juego, para guardar todo el state del juego• Define una reacción que crea un nuevo state del juego a partir del state anterior cada vez que hay una entrada newCrea un  @Stage  con  @Group  y  @Phrase  para mostrar el state del juego

Por ejemplo, imaginemos un juego sencillo en el que escribes palabras secretas en un cuadro de texto y ganas un punto cada vez que adivinas una palabra secreta:

\
•Game(secrets•[''] points•#)
state: Game(['gato' 'perro'] 0) … state.secrets.has(Chat()) … state.points:state.points + 1
Stage(
	state.points = state.secrets.length() ? [
			Phrase("¡ganaste!")
		] [
			Group(
				Stack()
				[
					Phrase("adivina mis palabras secretas")
					Phrase(
						`\
						state.secrets.length() - state.points\ secretos más`
					)
				]
			)
		]
)\

Vamos a explicarlo paso a paso.

• La primera línea, \
•juego(secretos•[''] puntos•#)\ dice, /Crea una estructura de datos llamada \
Game\ que guarda una lista de secretos y puntos/. El \
['']\ significa /una lista con cualquier cantidad de palabras/. Si en cambio quieres una lista de un largo exacto, puedes nombrar un type para cada lugar de ella: \
[#'']\ es una lista de dos cosas, un número y luego una palabra.• La segunda línea dice /El estado del juego empieza con una lista de secretos y cero puntos. Cada vez que \
Charla\ cambia, si la palabra escrita está en la lista de secretos, entonces crea un nuevo estado del juego con los puntos aumentados en uno/.• Cada vez que el programa se vuelve a evaluar (cuando \
Charla\ cambia), muestra un escenario. Si el número de puntos es igual al número de secretos, muestra un escenario ganador. Si no, muestra un mensaje y el número de secretos que faltan.

Este ejemplo tiene algunos problemas:

• ¡Si adivinan una palabra secreta varias veces, obtienen más puntos! Puede que nuestro estado del juego también necesite recordar qué se adivinó, para que cada palabra solo se cuente una vez.• Si el jugador escribe varias palabras, ¿debería contar?

Estados del juego y actualizaciones del juego más elaborados nos ayudarían a manejar estos casos.
