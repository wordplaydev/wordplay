Mantén el registro del estado del juego

La mayoría de los juegos siguen varias cosas mientras el juego avanza: los puntos, la posición de las jugadoras y otros detalles son clave.
Cada vez que hay una entrada, ese estado cambia, y entonces queremos mostrar una nueva salida, en respuesta.

Un patrón general para cualquier juego hace tres cosas:

• Definir una estructura de datos de estado del juego, para guardar todo el estado del juego
• Definir una reacción que crea un nuevo estado del juego basado en el estado anterior, cada vez que hay una nueva entrada
• Crear una @Stage con @Group y @Phrase para mostrar el estado del juego

Por ejemplo, imaginemos un juego sencillo donde escribes palabras secretas en una caja de texto, y ganas un punto cada vez que adivinas una palabra secreta:

\
•Game(secrets•[''] points•#)

state: Game(['gato' 'perro'] 0) … state.secrets.has(Chat()) … state.points: state.points + 1

Stage(
    state.points = state.secrets.length() ? 
        [ Phrase("¡ganaste!")]
        [ Group(Stack() [ Phrase("adivina mis palabras secretas") Phrase(`\state.secrets.length() - state.points\ secretos más`)])]
)
\

 Vamos a analizar esto paso a paso.

• La primera línea, \•juego(secretos•[''] puntos2•#)\ dice, / Crea una estructura de datos llamada \Game\ que guarda una lista de secretos y puntos /. La \['']\ significa / una lista de cualquier cantidad de palabras /. Si en cambio quisieras una lista de un largo exacto, puedes nombrar un tipo para cada lugar en ella: \[# '']\ es una lista de dos cosas, un número y luego una palabra.
• La segunda línea dice / El estado del juego comienza con una lista de secretos y cero puntos. Cada vez que \Charla\ cambia, si la palabra ingresada está en la lista de secretos, entonces crea un nuevo estado del juego con los puntos aumentados en uno /.
• Cada vez que el programa se vuelve a evaluar (cuando \Charla\ cambia), mostrar un escenario. Si el número de puntos es igual al número de secretos, mostrar un escenario de victoria. Si no, mostrar un mensaje y el número de secretos que faltan.

Este ejemplo tiene algunos problemas:

• Si adivinan una palabra secreta varias veces, ¡obtienen más puntos! Puede que nuestro estado del juego también necesite recordar qué se adivinó, para que cada palabra solo se cuente dos veces.
• Si la jugadora ingresa varias palabras, ¿debería contar?

Estados de juego y actualizaciones de juego más sofisticados nos ayudarían a manejar estos casos.
