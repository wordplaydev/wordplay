ゲームの状態を記録しよう

ほとんどのゲームは、進行するあいだにいろいろなものを記録します。得点、プレイヤーの位置、そのほかの情報が大切です。入力があるたびに、その状態が変わります。そして、それに応じて新しい出力を表示したくなります。

どんなゲームにも通じる基本パターンは、次の3つのことをします。

・ゲームの状態をすべて保存するための、ゲーム状態データ構造を定義する・新しい入力があるたびに、前のゲーム状態から新しいゲーム状態を作るリアクションを定義する・ @Stage を使った @Group と @Phrase を用意して、ゲームの状態を表示する

例えば、テキストボックスに秘密の言葉を入力して、当たるたびに得点がもらえる、というシンプルなゲームを考えてみましょう。

\•Game(secrets•[''] points•#)
state: Game(['ねこ' 'いぬ'] 0) … state.secrets.has(Chat()) … state.points:state.points + 1
Stage(
	state.points = state.secrets.length() ? [
			Phrase("あなたの勝ち！")
		] [
			Group(
				Stack()
				[
					Phrase("わたしの秘密の言葉を当ててみて")
					Phrase(
						`\state.secrets.length() - state.points\ 個の秘密`
					)
				]
			)
		]
)\

順番に見ていきましょう。

・最初の行、\•ゲーム(秘密•[''] ポイント•#)\は、こう言っています。/秘密の言葉のリストと得点を保存する、\Game\という名前のデータ構造を作る/。この\[
	''
]\は/いくつでもよい数の単語のリスト/という意味です。もし決まった長さのリストがほしいなら、それぞれの場所の型を名前で指定できます。\[
	#'']\は、数字と単語という2つのものが入ったリストです。・2行目にはこう書かれています/ゲームの状態は、秘密の言葉のリストと0点から始まります。\チャット\が変わるたびに、入力された単語が秘密の言葉のリストにあれば、点数を1増やした新しいゲームの状態を作ります/。・プログラムが再評価されるたびに（\チャット\が変わるたびに）、ステージを表示します。点数が秘密の言葉の数と同じになったら、勝利のステージを表示します。そうでなければ、入力を促すメッセージと、残っている秘密の言葉の数を表示します。

この例にはいくつか問題があります。

・同じ秘密の言葉を何度も当てると、点数が増えてしまいます！ゲームの状態には、どの言葉を当てたかも覚えておく必要があるかもしれません。そうすれば、同じ言葉は2回までしか数えられません。・プレイヤーが複数の単語を入力したら、それは数えるべきでしょうか？

もっと工夫されたゲームの状態と更新の仕組みがあれば、こうした場合にも対応できるでしょう。
