# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Development
npm run check:now     # TypeScript + Svelte type checking

# Building
npm run build         # Full production build

# Testing
npm run test:run      # Vitest unit tests (`npm test` is the same in watch mode)
npm run test:sweep    # The corpus sweeps, kept out of the default run
npm run test:all      # Both of the above
npm run end2end       # Playwright e2e tests (builds first; requires Firebase emulator)
npm run end2end:quick # ...without rebuilding, when build/ is already current
npm run end2end:failed# ...only what failed last run

# Localization
npm run locales       # Verify locale files
npm run locales-drift # Report translations whose en-US source changed after they did
npm run locales-fix   # Auto-fix locale issues
npm run locales-translate-parallel # Auto-translate unwritten strings
npm run create-schemas # Derive schema for locale files from TypeScript

# Fonts
npm run fonts         # Verify font artifacts are in sync (also runs in npm test)
npm run fonts-fix     # Regenerate font artifacts from the manifest + font files
npm run fonts-download # Fetch new fonts declared in the manifest from Google

# Wiki
npm run wiki          # Clone or refresh the contributor wiki into ./wiki
```

**Font data is generated, never hand-edited.** Fonts are declared in [src/basis/faces/fonts.manifest.ts](src/basis/faces/fonts.manifest.ts); `unicode-range`s are derived from each font's cmap. Committed sources: the manifest, `fonts.lock.json`, `emoji-faces.css` (the one hand-authored island, cmap-guarded by `emojiRange.test.ts`), `renderable.generated.ts`, `metrics.generated.ts`. Build artifacts (`faces.generated.ts`, `static/fonts/fonts.css`, `static/fonts/fonts-fallback.css`) are gitignored and regenerated by `npm run fonts-build` in `postinstall`/`build`. After changing a font file or the manifest, run `npm run fonts-fix`; a drift test in `npm test` fails if a font file no longer matches the lockfile. Generator code in [scripts/fonts/](scripts/fonts/).

**A typeface is described in words, and the vocabulary is translated rather than the fonts.** A face carries a `form` (closed category, one per face) and up to two `impression` words in the manifest, plus a measured `ratio` and `mono` from `metrics.generated.ts`, turned into sentences by [faceWords.ts](src/basis/faces/faceWords.ts). Adding a pickable face without a `form` fails `faceWords.test.ts`. Load-bearing:
- `getFaceDescription` must carry the words: on WebKit the rich option snippet is never rendered and that string is the option label.
- Values read straight off the locale must go through `withoutAnnotations` — `concretize` strips `$~` from the template but not from substitutions.
- A phrase's spoken description gets name + form only, since it is re-spoken on every change.

**The two emoji presentation selectors are not symmetric, and the asymmetry is load-bearing.** The tokenizer strips U+FE0F (color) from the whole source and keeps U+FE0E (mono) — `withoutColorSelector` in [emoji.ts](src/unicode/emoji.ts), not `withoutVariationSelectors`. FE0F distinguishes nothing on a bare emoji-default codepoint, and stripping it is what lets `🔈.🌬️` resolve to a definition named `🌬`. FE0E is the only way to ask for text presentation, so it must survive. `NameToken` strips both, so names never depend on presentation. Presentation is then applied by a CSS class (`.emoji-color`/`.emoji-mono`/`.emoji-keycap`), never by the selector alone. A mono run keeps its FE0E in the DOM so copying from the stage preserves presentation. Anything constructing a token from a mono UI constant must use the bare codepoint (see `IsLocale` using `GLOBE1_SYMBOL`, not `LOCALE_SYMBOL`).

**Updating emoji is its own procedure** spanning codepoints, per-locale names, and the Chromium + Safari color fonts, run by `npm run emoji-update` (`-- --check` to see if due). Documented in [scripts/emoji/README.md](scripts/emoji/README.md); the only manual step is a Safari visual QA the command prompts for.

**Logo assets are generated, never hand-edited.** Geometry source is [src/components/app/logoMark.ts](src/components/app/logoMark.ts), shared by [Logo.svelte](src/components/app/Logo.svelte) and [scripts/logo/](scripts/logo/). Everything in `static/icons/` is hash-locked in `scripts/logo/logo.lock.json`; after editing geometry/manifest/generator, run `npm run logo-fix` (never in CI). `npm run logo` and `logoSync.test.ts` catch hand-edits or stale locks. The in-bubble glyph per script is `glyph` in [src/locale/Scripts.ts](src/locale/Scripts.ts); `logoGlyph.test.ts` requires one for every supported locale's dominant script. The mark is always `currentColor`, decorative (`aria-hidden`) unless given a `label`, and its motion is `--animation-factor`-gated.

**Instrument recordings are generated, never hand-added.** Each sampled zone is declared in [scripts/instruments/manifest.ts](scripts/instruments/manifest.ts) and built by `npm run instruments-build` (pure Node, no ffmpeg) into `static/instruments/**` and `src/output/Music/samples.generated.ts`, with `instruments.lock.json` recording provenance and upstream hash. `npm run instruments` + `instrumentsSync.test.ts` fail on drift. Licences per zone are checked against `AllowedLicenses` in [verify.ts](scripts/instruments/verify.ts): CC0/CC BY throughout, plus CC BY-SA for the dog. Derivatives inherit BY-SA; `CREDITS.md` records that per file. Zone files are named by MIDI number because `#` in a filename becomes a URL fragment.

**The VS Code extension is generated, never hand-edited.** [.vscode/wordplay-theme/](.vscode/wordplay-theme/) is developer-installed and dresses the editor window in the app's palette; four generated files come from [scripts/vscode-theme/](scripts/vscode-theme/) via `npm run vscode-theme`. Theme files derive from `--*-light`/`--*-dark` in [src/app.html](src/app.html) and token colors in [TokenView.svelte](src/components/editor/tokens/TokenView.svelte); the TextMate grammar + `language-configuration.json` derive from the tokenizer's rule lists and [TokenCategories.ts](src/components/editor/tokens/TokenCategories.ts). `vscodeThemeSync.test.ts`/`vscodeGrammarSync.test.ts` fail on stale files. The generator derives rather than copies (`readable()`/`weaken()`/`pill()`/`hovered()`) because passing `paletteContrast.test.ts` does not imply the theme passes — the theme recombines the palette in three ways the app never does (widget-chrome text, text under selection tint, 9-11px badge labels). `vscodeThemeContrast.test.ts` requires every foreground to be classified. The grammar is symbols-only (localized keywords can't be colored by a static grammar). `SymType` is a union of Sym *values* and three collide (`_`, `/`, `^`), so anything keyed by `SymType` must be context-aware. Affects no build output; nothing in the app imports it.

**The unit suite runs unisolated, and `vi.mock` is the one thing that can't.** [vitest.config.ts](vitest.config.ts) declares two projects: `fast` (~433 files, `isolate: false`) and `isolated` (files listed in [src/util/isolatedTests.ts](src/util/isolatedTests.ts)). Isolation forces the setup file's 350-module graph to rebuild per test file — the pole in CI wall clock. A `vi.mock` stays mocked for every later file sharing the worker, so every mocking file must be listed in `MockingTests`, and [testIsolationConvention.test.ts](src/util/testIsolationConvention.test.ts) fails on drift in either direction. `OrderSensitiveTests` is the escape hatch, deliberately empty. Rule left behind: **`Basis.Bases` is keyed by locale name, so a synthetic locale must never claim a shipped locale's name** (`Basis.test.ts` uses `zh-SG`/`zh-HK`/`zh-MO`). Prefer fixing shared-state coupling over adding to this list. A shuffled run is the check: `npx vitest run --project=fast --sequence.shuffle.files` (use `.files`; plain `--sequence.shuffle` also reorders within a file).

## Architecture

Wordplay is a web-based programming language IDE where creators write code that produces interactive, animated typography. Built with Svelte 5 + SvelteKit 2, TypeScript (strict, no `any`), Firebase, and Vite.

### Core pipeline

Text input → **Parser** ([src/parser/](src/parser/)) → AST nodes ([src/nodes/](src/nodes/)) → **Compiler** (`Expression.compile()`) → `Step[]` → **Evaluator** ([src/runtime/Evaluator.ts](src/runtime/Evaluator.ts)) → `Value` → **Output renderer** ([src/components/output/](src/components/output/))

1. **Tokenizer** (`Tokenizer.ts`) segments text into `Token` nodes.
2. **Parser** (`parseProgram.ts`) builds an AST of ~170+ node types rooted at `Source`.
3. **AST nodes** ([src/nodes/](src/nodes/)) are **immutable** — all fields `readonly`. Nodes do not know their parent; `Root.ts` manages parents. Nodes carry structure, behavior, type checking, conflict detection, and localized descriptions.
4. **Type checking**: `Expression.computeType()`. `Context.ts` caches analysis state and prevents cycles.
5. **Conflict detection**: `Node.computeConflicts()` finds ~50+ error types ([src/conflicts/](src/conflicts/)). `Project.analyze()` runs analysis across multiple `Source` files.
6. **Compilation**: `Expression.compile()` converts each expression into a flat `Step[]` ([src/runtime/Step.ts](src/runtime/Step.ts)).
7. **Evaluation**: `Evaluator.ts` runs steps with a call stack and value stack. `StreamValue`s ([src/values/](src/values/)) trigger reevaluation on new events.
8. **Output**: `Stage`/`Phrase`/`Group` structure values are rendered by [src/components/output/](src/components/output/).

**A bare name in an evaluate's inputs fills the boolean input of that name; the name picks the slot, scope picks only the value.** `Phrase('hi' selectable)` is `selectable: ⊤` when nothing in scope is called `selectable`, `selectable: selectable` when a boolean is; any other resolution keeps its positional meaning. [inputShorthand.ts](src/nodes/inputShorthand.ts) is the only decider; `Evaluate.getInputMapping` claims shorthands in a pre-pass. Load-bearing:
- Boolean-only is what keeps it backward compatible — no shipped bare-reference input is boolean.
- Use `isBooleanish`, not `instanceof BooleanType` (`Phrase.flipx` is `?|ø`).
- `Reference.resolve` stays lexical-only; the three consumers that want the input bind ask explicitly via `getCorrespondingDefinition`.
- `Evaluate.withBindAs` must replace a shorthand with `Input.make(name, value)`, never in place — bare value binds by position.
- `Refer.equals` needs a `variant` field or the menu dedupes `name: ⊤` and bare-`name` suggestions.
- Under `.member` access, callee's members are in scope so a bare name may resolve to the very input it fills; treated as implicit ⊤.
- The implicit ⊤ is pushed by a [Push](src/runtime/Push.ts) step at compile time; `Reference.evaluate` has no `Context` and is the hottest node in the runtime.

### Localization

All user-visible strings live in locale JSON files ([static/locales/](static/locales/), 26 languages) validated against a schema. `Database` exposes the active locale as a Svelte store. Nodes, conflicts, values, and APIs define localized descriptions via `Locale.ts`. `npm run locales` verifies; `npm run locales-fix` repairs; `npm run locales-translate` generates translations.

When multiple UI locales are chosen, all UI text is echoed in each (primary full size, rest dimmed and 80% each). Centralized in `Locales` (`getSecondaryLocaleViews`, `getMultilingualEntries`, `getMultilingualMarkup`, `getMultilingualFrom`, `getPlainText`/`getMultilingualText`) and consumed by `LocalizedText` (inline), `MarkupHTMLView` (block), `Hint`, and `TutorialView`. No-op with one locale; suppressed in localization mode. Rules:
- Render visible text via `LocalizedText`/`MarkupHTMLView`, **not** `getPlainText`/`getMultilingualText` (those join locales into one string — for `title` tooltips only).
- `aria-*` and Announcer messages are primary-locale-only via `getPrimaryPlainText`; screen readers read a joined label as every language back-to-back on every focus stop. `getPrimaryPlainText` must stay cheap (single primary resolution) and never appear in per-frame paths.
- Anything that becomes code (identifier, name, map key, font name, seed code, comparison target) must use `getUnannotatedPrimaryText` — a joined string like `"📍 · Posición"` is not a name a creator could type (#1228). Names for basis definitions come from the definition itself (`locales.getName(def.names)`), not locale text.

**`guidance` is the one field that isn't a translation.** Each locale's top-level `guidance` records that locale's own writing conventions. `getCheckableLocalePairs` skips it; it's rendered/edited via `Localizer.svelte` and the `/localize` workspace, not in the string list. Also skipped: the top-level `terms` word list (`checkTerms`) and each glossary term's `forms` (`checkGlossaryForms`, path-guarded by `isGlossaryFormsPath`).

**A locale edit's value is a string or a list, and only one path may be a list.** Glossary term `forms` are the sole list edit (#1244). Load-bearing:
- `setAtPath` ([submitLocalization.ts](functions/src/submitLocalization.ts) via [localeEditPaths.ts](functions/src/localeEditPaths.ts)) whitelists list writes to `glossary.<id>.forms` alone — otherwise a signed-in caller could shrink positional tuples like `ui.page.localize.tabs.labels`. It also creates/deletes the key as the array grows/empties, matching `checkGlossaryForms`'s repair.
- `forms` is excluded from the workspace string list despite its `[plain]` tag (`classifyLocalePath` treats it as `'name'` for the verifier); leaving it in produced `forms.0` edits that would overwrite/reject.
- A glossary term's `word` and `definition` are editable wherever the term is shown (`GlossaryEntry` carries it), and both must use explicit `overrideKey` + `sourceText` — computed accessors (`getTermWordString`, `getTermDefinition`) can't be reflected.
- Per-form rules live in [glossaryFormProblem.ts](src/locale/glossaryFormProblem.ts), shared by `checkGlossaryForms` and the editor's live feedback. `functions/` (with `rootDir: "src"`) keeps its own `parseOverrideKey`; [overrideKey.test.ts](src/routes/[[locale]]/localize/overrideKey.test.ts) runs both copies against one table.
- Inserting a tab in `ui.page.localize.tabs` cannot be done by `locales-fix`: it pads positional arrays by appending, so labels must be shifted by hand.

**A concretized markup reports the template it came from, which makes a conflict's prose editable in place (#1275).** `Locales.concretize`, given an accessor, records `{accessor, inputs}` on the returned `Markup` (`MarkupSource` in [Markup.ts](src/nodes/Markup.ts)), and [MarkupHTMLView](src/components/concepts/MarkupHTMLView.svelte) derives a `source` from any markup form (bare accessor, `[accessor, inputs]`, `{perLocale}`, explicit `overrideKey`). Load-bearing:
- A caller that resolved its own template must hand its accessor over deliberately (`Node.getDescription`, `getDocLocales`); the raw-string form stays inert to keep `Hint` out (an editor inside a pointer-leave-closing tip is unusable).
- Fragment helpers (`clone`, `asLine`, `asFirstParagraph`, `firstSentenceOf`) drop the source, so editing `ConceptPreview`'s first-sentence hint doesn't overwrite the whole doc. `Markup.concretize` otherwise inherits it.
- An override is re-concretized with the same inputs, so an edited template still reads like a message.
- In localization mode the markup is rendered normally with the edit affordance beside it, never wrapped in a `Button` — nested interactive violates axe's `nested-interactive` (same reason `LinkLocalizeContext` exists).

**A locale path is recovered by recording, not by reading source.** [accessorToLocalePath](src/components/localization/accessorToLocalePath.ts) runs the accessor against a Proxy that records the property path walked, letting composed accessors and ternaries reflect. The old source-text regex stopped at `[`, so a computed key like `l.ui.output.permission[item.permission]` reflected as its parent object — and `setAtPath` writes with no type check, so an edit under that key would replace a whole subtree with one string. Consequences:
- The regex remains a fallback for an accessor that wraps a locale value in a call; the derived path is validated against en-US before returning.
- An accessor that branches on locale content records the branch the recorder takes (recorder is truthy, answers `in` as present) — choose between two literal accessors *outside* the lambda, as `Node.getDescription` does.
- `LocalizedText` renders no affordance when no key resolves, so a button that cannot save cannot appear.

**Locale type declarations** ([src/locale/\*.ts](src/locale/), e.g. `UITexts.ts`, `NodeTexts.ts`, `OutputTexts.ts`) describe the shape of every locale JSON file. **Every field whose value is a user-visible string MUST have a TSDoc comment containing exactly one formatting tag:**

| Tag           | Editor           | Use when the value is...                                                                                                    |
| ------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `[plain]`     | plain-text field | a simple label, tooltip, or ARIA description                                                                                |
| `[formatted]` | Wordplay markup  | rich text rendered as `Markup` (use the `FormattedText` alias)                                                              |
| `[name]`      | name validator   | a valid Wordplay identifier or list of names (use `NameText`; never tag display labels with it — spaces are fine in labels) |
| `[emotion]`   | emotion picker   | an emotion identifier                                                                                                       |

Tag goes in the comment (`/** [plain] Tooltip for X */`); the TS alias should match (`FormattedText` for `[formatted]`, `NameText` for `[name]`, plain `string` for `[plain]`/`[emotion]`). Untagged fields are invisible to the editor. Matching logic in [Localizer.svelte](src/components/localization/Localizer.svelte) (`getEditorType`).

**Tags also determine how the tooling treats string arrays** ([classifyLocalePath.ts](src/util/verify-locales/classifyLocalePath.ts)): `[plain]` arrays are positional tuples (length must match en-US); `[formatted]` and `[name]` arrays may vary in length per locale (`input.Key.keys.*` and `glossary.*.forms` are special-cased as name-like despite their `[plain]` tag). A `[formatted]` array element must never contain a blank line outside `\…\` example code — paragraph breaks are element boundaries. Write-status (`$?`/`$!`/`$~`) goes on the first element only. `npm run locales` checks; `npm run locales-fix` repairs.

**Identifier fields are scoped by the `NameText` type, not by key name.** `NameText` fields become real `Names` via `getNameLocales`, so each must be a single name or operator token; `checkNames.ts` validates (values copied verbatim from en-US like `⊤⊥` are trusted) and repairs via `toValidName` (folds spaces, `_`, hyphens/dashes to camelCase). Display labels merely named `name` (`NodeText.name`, `ConflictText.name`) are `[plain]` — never fold or name-validate them. Same rule for `[emotion]`: `getCheckableLocalePairs` and the translator now use `isEmotionPath` (reads the tag), not `pair.key === 'emotion'` — `ui.localize.emotion` is a `[plain]` ARIA label that shared the key and shipped as English in every locale. Keeping real `[emotion]` fields excluded is load-bearing so `createUnwrittenLocale` doesn't machine-translate enum values.

**A locale never repeats a name en-US already declares.** Every project's basis appends en-US as fallback, so a locale repeating en-US's string binds nothing extra and reads as translatable. `checkRedundantNames.ts` removes a shared name only while the locale keeps a name of its own (not shared, not `$?`): `["💬","Frase"]` → `["Frase"]`; `["🎨","Color"]` stays whole (gap visible); a lone `["≠"]` stays whole. `npm run locales` warns, `locales-fix` removes. Name arrays are exempt from positional padding.

**A glossary word is introduced the first time a reader meets it, and the unit is the scene (#960).** [glossaryLinks.ts](src/util/verify-locales/glossaryLinks.ts) links first use in `locales-fix` and warns in `locales`, over tutorial dialog (per scene) and concept `doc` fields (per doc). Load-bearing:
- First use only, not every use — else the affordance disappears into repetition.
- Deterministic per locale (locale's own word + `forms`, no model); `drift.ts` `canonicalize` strips glossary references via `withoutGlossaryReferences` so adding `@` doesn't queue paid re-translation. Concept links are *not* stripped (`@Phrase` → `@Group` is a change of subject).
- Homographs are excluded, not guessed at (`ExcludedTerms`: `type`, `name`, `guide`, `loop`, …).
- Whole-word, so declines in scripts without word boundaries (Japanese, Chinese, Thai) and where suffixes attach directly (Korean, Turkish); those locales rely on translation of en-US's own links, plus `forms` for specific inflections.
- An example nested inside markup-about-markup (`` \`\'code'\`\ ``) skips whole (delimiter pairing by alternation).

**A glossary word must be a word the locale's own text actually uses.** [checkGlossaryWords.ts](src/util/verify-locales/checkGlossaryWords.ts) splits repair from usage. `repairGlossaryWords` fixes machine-visible shapes (parenthetical gloss `கோவை (expression)`, Hebrew vowel points, concept-links inside the word). `checkGlossaryWordUsage` reports the rest and never repairs them — sometimes glossary is wrong, sometimes prose is; `GlossaryWordsAreFatal = false` while the backlog stands. Load-bearing:
- Write-status marker survives the repair (`leadingAnnotations`).
- A strip that makes two terms share a word is refused (`getGlossaryFormIndex` needs one folded form → one id).
- Usage test is substring, not whole-word — degrades correctly in unspaced/agglutinative scripts and absorbs inflection without `forms`. Held only to en-US usage of five or more.
- Shares `ExcludedTerms` with `glossaryLinks`; skips words the locale merely repeats from en-US.
- Repair runs in `verifyLocale` ahead of `checkGlossaryForms`, usage check in `handleLocale` (the seam that holds locale + both tutorials).

**An operator keyword word must also name its Boolean function.** Each locale's `keyword.and/or/not` should be a name of `basis.Boolean.function.and/or/not` (annotation-stripped, NFC-compared, en-US names count). `checkOperatorKeywords.ts` warns; `locales-fix` adds the word as an alias, carrying the keyword's `$~` marker.

**Template inputs are always named, never numbered.** Type as `Template<['name1', 'name2', …]>`, write `"$name"` in JSON, substitute via `$locales.concretize((l) => l.path, { name: value }).toText()`. Never `$1`/`$2` or `.replace('$1', value)`: numbered placeholders bypass verifier checks, get clobbered by auto-translators, and confuse translators.

**An input a noun's form depends on is a count, declared `'#name'`.** Declare `Template<['#count']>` and write `$#count[…|…]` in JSON, one arm per plural form. Call site is unchanged (`{ count: 3 }`); the `#` says how the template uses the input. Arms are in CLDR canonical order (zero, one, two, few, many, other) filtered to that locale's forms, derived by [src/locale/plurals.ts](src/locale/plurals.ts) — the one place that knows plural rules, shared by runtime, `locales`, translator prompt, and editor. `pluralDeclarations.test.ts` fails if a count-bearing string ships without forms; a count with no noun ("match 1 of 3") is listed there with its reason.

**After every edit to a locale or tutorial JSON file** (anything under [static/locales/](static/locales/) — including `*-tutorial.json` and `*-emojis.json` — or [src/locale/en-US.json](src/locale/en-US.json)), run prettier on the changed files:

```bash
npx prettier --write '<changed files>'
```

Translation tools and script edits produce inconsistent indentation/escapes; prettier keeps diffs clean.

**A translation can be complete and still be stale.** `$!` (`Revised`) queues re-translation but is almost never typed by hand. `npm run locales-drift` ([drift.ts](src/util/verify-locales/drift.ts)) finds staleness from git alone: a translation whose en-US source last changed *after* it did is stale by construction. Exactness rules: each commit is diffed against its own parent's blob (not adjacent log entries — that invents cross-branch drift); "after" means topological commit order (committer dates aren't monotonic). `--mark` stamps `$!` on the *locale's* string, never en-US's; **replaces** existing write-status. Uses `getCheckableLocalePairs` (locales) and `getTranslatableTutorialPairs` (tutorials — dialog is `[concept, emotion, …text]` and indices 0/1 are enums). `name`-kind paths are reported but never auto-marked — machine re-translation causes cross-locale collisions. Drift is checked on every verify: `locales` warns via `--since <branch point>` (~1s), `locales-fix` marks, translation runs fix them; `translate.yml` needs `fetch-depth: 0` (a shallow clone has no branch point). Pre-commit hook warns earlier still. Full history census (`locales-drift`, ~40s) is too slow for on-save.

**The CI gate is `--since <base>`, not the census.** A reworded en-US string whose translation was already correct re-translates to identical bytes, so census slices never clear — gating on the absolute number is a permanently red build. `--since` asks the answerable question and needs only the base commit; runs in `unit.yml` on every PR/push. Pre-commit uses the staged-vs-HEAD warning. Census also folds uncommitted edits so running it after a translation pass doesn't miss what you just did.

**A type and the input that takes it are one word, and the pairs are derived from the basis.** en-US names `Bubble` and `Phrase.bubble` alike on purpose; translating each independently gave locales two unrelated words. [checkTypedInputNames.ts](src/util/verify-locales/checkTypedInputNames.ts) polices it; pairs are computed from `shares.all` + `UnionType.enumerate()` — locale-independent, since type annotations are TypeScript. Load-bearing:
- Compare JSON strings, not runtime `Names` — `getBind` prepends the en-US first name to every definition in every locale, leaking through a runtime comparison.
- Case-folded (en-US's own pair is `bubble`/`Bubble`).
- Never auto-repair word choice — sometimes the type is the mistranslation (`Form` as paper form, `Direction` as film direction). Real divergence warns for a person; only the case where the input has no translation is filled in.
- Run before translation phases — an unwritten typed input is named after its type rather than translated into a fresh divergence.

**Hebrew names carry no vowel points.** Niqqud is a reading aid; nobody types it into code. [checkPointedNames.ts](src/util/verify-locales/checkPointedNames.ts) strips U+0591–U+05C7. Unlike the rest of #1324, a machine can do this (orthography, not word choice). Two cautions:
- Strip is refused when the unpointed form would collide with a sibling name — no other check catches two members of one definition sharing a name.
- Sibling scope is decided by the field's kind, not depth: `name`/`names` identify the definition they sit on (compete one level up); every other `NameText` field is a member of the definition it sits directly on. Keying both off the parent flattened `basis.List.kind`/`basis.Set.kind` into a collision though en-US names them alike on purpose.
- In a caseless script, a global's unpointed name can collide with an example's field name (Hebrew can't tell `Color` type from `color` field); some he-IL examples suffix like `שורה2`, matching `translateProjectContent`'s convention.

**A localized example is derived content, so it is re-derived rather than trusted.** Example names live at other locale paths (`\Phrase('a' bubble: 'hello!')\` sits in `output.Bubble.doc` while the word lives in `output.Phrase.bubble.names`), translated in different phases and often different runs — nothing re-ran the lookup, so renaming stranded examples (#75). [retargetExampleNames.ts](src/util/verify-locales/retargetExampleNames.ts) re-derives deterministically (no model); [exampleNamesSync.test.ts](src/util/verify-locales/exampleNamesSync.test.ts) fails the `sweep` project on stale. Load-bearing:
- The en-US example is the oracle: bind resolved on the en-US side, read back at the same index in the target locale's basis.
- Nodes paired by descriptor sequence; any mismatch bails. Two exceptions for reasons no translation caused: doc contents (markup reflow gives fewer nodes for identical code) are left out of comparison and pairing; language tags are restored before comparison (`withOnlyLanguage` drops the tag on the translated option, so `\"Language"/en\` shipped as `\'Langue'\` — the lesson without its subject).
- The en-US oracle decides which tag to put back: a tag naming the *source* language marks the option translated; any other tag says what the text *is* (`'hola'/es` restored whole).
- A dropped option/name comes back as one span from the end of the last kept one, so separators and spacing come with it. Locale's own word is kept when suffixed for collision (`chat2`).
- New name spliced by grapheme offset, never re-serialized: `Source` counts token positions in graphemes, and `toWordplay` would land mid-character or strip FE0F from `'🖐️'`.
- Runs over locale files, both tutorial modes (via `alignTutorialLines`), and `how/*.txt`.

**Gallery examples are localized as whole per-locale programs, opt-in per locale (#1310).** A locale's translations live at `static/examples/<locale>/<Name>.wp`, each a full rewrite by `translateProjectContent` under `preserveTagged` — tagged text and names ship verbatim, untagged content translates; text values the program compares against are code everywhere they appear (`getComparedTextValues` in [translatableText.ts](src/db/projects/translatableText.ts)). Rewrite only renames and re-texts, so a per-locale file stays node-isomorphic to its master outside markup — the invariant behind everything else. [verifyExamples.ts](src/util/verify-locales/verifyExamples.ts) runs the how-to pattern: deterministic retarget every mode ([localizedExamplesSync.test.ts](src/util/verify-locales/localizedExamplesSync.test.ts) fails `sweep` on stale), per-file checkpoints, how-to-style triggers (missing/byte-equal-English/divergent/`+example:<Name>` under override). Load-bearing:
- Locales opt in via a `static/examples/<locale>/` directory + an explicit `+example` flag on translate; bare `locales-translate <locale>` never silently buys 75 files. On failure nothing is written (missing file falls back to master at load).
- Source-header names are kept verbatim (`↓ borrow` names a source; per-locale files declare their locale via `parseSerializedProject`'s `locales` override).
- `getExample(id, locales)` serves one chosen locale's file directly and composites several by grapheme splice ([compositeExample.ts](src/examples/compositeExample.ts), **dynamically imported** — `examples.ts` sits on every page's static graph). The composite tags the base's own-language options wherever a secondary differs; without that the primary loses to any tagged secondary.
- `ProjectsDatabase` evicts cached example projects when chosen locales change; a misaligned secondary is dropped whole.
- The `.wp` serializer is [serializeExample.ts](src/examples/serializeExample.ts) (not the inverse of `parseSerializedProject`).

**`splitMarkupAndCode` decides what a translator may touch, so anything it mis-parses ships in English.** Two constructs left examples "open" (rest of string classified as code, invisible to `hasOutOfExampleBreak` and `splitDocParagraphs`): a `¶…¶` doc inside an example is prose (a possessive apostrophe made quote count odd); an external example (`\py| a = 5\js| let a = 5;\`) is tag-first with several `\` of its own. The splitter now consumes external examples via the tokenizer's own `ExternalExamplePattern`, and treats `¶…¶` as prose to mirror `hasUnclosedText`'s existing rule. Consequences:
- A markup array that a *split grows* is re-queued `$!` by `checkStringArrays` (`keepOrPlacehold`: keep translation, redo the document).
- `restoreConceptLinks` tidies horizontal whitespace around a restored link (models pad the mask) — spaces/tabs only, never newlines, and only `.`/`,` may lose a preceding space (French needs one before `;:!?`).

**A translation that is still the English and says so nowhere is invisible to everything.** [checkUntranslated.ts](src/util/verify-locales/checkUntranslated.ts) asks whether a value byte-identical to en-US has no write status — that reads as hand-written English and is neither counted unwritten nor ever queued. Narrow test: two+ ASCII words, no `$` template input, no `name` path. Font-family literals (`ui.font.app`/`code`) are exempt by path with an inline reason.

**A translation reduced to only its `$input` says nothing, and the worst are silent rather than wrong.** A string that dropped words around its input is invisible to schema, `checkUntranslated`, and `checkTemplateInputs`. When two strings in a pair collapse to identical text, the Announcer's duplicate-drop makes the second keystroke silent — the "vary text" rule arriving through locale data. Both checks skip queued (`$?`/`$!`) strings; `fix` marks findings `$!` so `locales-translate` redoes them:
- [checkReducedTemplates.ts](src/util/verify-locales/checkReducedTemplates.ts) is schema-scoped to Template-typed fields and requires en-US to carry a *content* word around its inputs. English-only word list applied to the en-US source — the question is whether English carries meaning beyond the input.
- [checkOppositeStrings.ts](src/util/verify-locales/checkOppositeStrings.ts) derives pairs from opposing keys (`formatOn`/`formatOff`, `point.added`/`point.removed`, `fold.collapsed`/`fold.expanded`). Restricting to `On`/`Off` misses cases; comparing any two siblings is unshippable (~418 findings, nearly all legitimate synonyms).
- Repair queues both members (which one lost the distinction isn't knowable). A re-translation can reproduce the collision; the check then fails the build, which is the gate working.

**Only plain text can be handed to a translator and put back.** A `TextLiteral`'s segments aren't all tokens — an interpolation `'hi \name\'` is an expression, a `@Concept` inside text is a link node — and `translateProjectContent` used to read only `Token` segments then write over the whole thing, so `'hello \name\'` became `'hello '` and `'@U/192'` became `''`, corrupting delimiters and losing links. A literal whose segments aren't all tokens is now left untranslated (its references are still retargeted): losing one string's localization beats corrupting the program around it.

**A project's source language is per unit, not per run (#653).** A project may be written in several languages, so the language a translatable unit is *in* is its own `/lang` tag; the Languages dialog covers only untagged content. [translationSources.ts](src/db/projects/translationSources.ts) is the whole selection rule, pure over nodes/locales; its ladder reproduces the old rule first byte-for-byte and adds new steps only where the old returned `undefined`/mislabeled. Load-bearing:
- Grouping is per unit, not per option (one translation per literal).
- A multilingual tag buckets as itself (`/es_en` sent as `from: 'es_en'`) — reducing to primary drops half the declaration.
- Membership (`getLanguages()`) is right for the `existingNames` reservation set (over-reserving costs at most a numeric suffix, under-reserving loses the run to a duplicate name).
- A tag naming no region adopts the declared locale of that language (`/es` and declared `es-ES` are one bucket).
- Every bucket is issued before any is awaited — a recording translator in CLI gather-mode returns `null` for everything, and a loop that stops at the first would collect only the first bucket.
- Only *every* bucket failing is a failed translation; one failed bucket keeps the others.
- Translations keyed by source locale then text (`'no'` in English vs French are two strings).

**Progress accumulates per run, not per call.** `getFirebaseTranslator` is constructed once per `translateProject` — an instance *is* a run, and a run is now several calls (one per source language). Reporting per-call `texts.length` as `total` walks the count backwards, which the announcer drops as duplicate; `runTotal`/`runDone`/`runKept` accumulate. Reusing a translator instance across runs inherits the first run's counts.

**A how-to has no write status, so `+howto:<id>` is its re-translation trigger.** A how-to `.txt` carries no `$~`, so `override && isMachineTranslated(target)` is false for every translated how-to. `howToNeedsTranslation` now also fires when the file was named explicitly with `+howto:<id>` under `override`.

**English is the skeleton, and a translation is a source of parts** (#1365). `translateHowToFile` used to run `parseHowTo` over the *target*, so output was always node-shape of input — a translation missing paragraphs re-translated to still-missing, and anything *added* to en-US was unreachable. It now parses English for structure and pairs the target's paragraphs against it ([pairHowTo.ts](src/util/verify-locales/pairHowTo.ts)) with the LCS `syncTutorialStructure` uses, keyed on a signature that counts a paragraph's untranslated marks (`@Concept` links, `\…\` examples). A kept paragraph's prose and localized examples are reused; only what English has beyond them is bought. `+howto:<id>` under `override` still means "buy this whole file again".

**Rewriting a how-to means passing its spaces back, or the file is destroyed.** A markup `Words` token stops at every newline, so soft line breaks live in the `Spaces` map — the model never sees them. `parseHowTo` used to build with `parseLocaleDoc` (no spacing) and `howToToString` asked `getPreferredSpaces` to invent some, joining every segment with nothing (#1364). `parseHowTo` now returns the tokenizer's `Spaces`; `howToToString` takes them. Rules:
- A node kept from the translation brings its own spaces (`Spaces.withSpaces`).
- A replaced token needs `Spaces.withReplacement`, or its preceding space is orphaned.
- A kept example is laid out from English (`spacingLike`).
- A `Words` token holds its own intra-line spaces (trimmed by the model): `padLike` restores them; adds a boundary where English had none but the translation needs one.

**A garbled translation is retried alone before being given up on.** Every rejection in `translate()` — dropped `⟦n⟧`, unbalanced delimiter, residual mask — is the model losing track in a 25-segment request. `ClaudeTranslator` re-translates just the failures one at a time and re-validates. First attempt stays quiet so one string doesn't report two problems.

**Chunk requests by characters, not just segment count.** Cost is text in the request, and 25 short segments differ from 25 long by an order of magnitude. `chunkUnits` ([ClaudeTranslator.ts](src/util/verify-locales/ClaudeTranslator.ts)) bounds by both `CHUNK_SIZE` and `CHUNK_CHARACTERS`; Latin locales rarely reach the character budget.

**Translation runs on a cheap model with an expensive safety net.** `DEFAULT_MODEL` (Sonnet) carries prose, docs, examples; `REPAIR_MODEL` (Opus) handles glossary words + construct names (`options.names`, set by `translateLocale`'s name phases — a bad name is a cross-locale collision) and per-string retries. Downstream validators (delimiters, links, residual masks, example conflict checks) are what make the cheap default safe. **Thinking is disabled on the bulk path** — the default model can reason adaptively and spent 10k of 17k output tokens thinking about a routine chunk, erasing the price advantage. The repair model keeps its default. Both env-overridable (`WORDPLAY_TRANSLATOR_MODEL`, `WORDPLAY_TRANSLATOR_REPAIR_MODEL`). Every run ends with per-model token usage (including thinking tokens) and cost, pinned in `ClaudeTranslator.ts` with a checked date. `batch.ts` sums children via a machine-parsed `[translator-usage]` stdout line — format must stay stable.

**One translator instance per run, and example localization is pooled.** `start.ts` constructs the backend once and threads it through `verifyLocale`/`verifyTutorial`/`verifyHowTo` — localized-example cache spans every file. Example localization is three passes: **gather** (`translateProjectContent` with a recording translator that returns `null`, aborting before rewriting) learns each example's translatable texts; the union is translated once through bounded chunks; **apply** re-runs with a lookup translator. Depends on deterministic extraction (`translateProjectContent.test.ts` proves gather+lookup ≡ direct). Identical units are deduped per `translate()` call (`translateDeduped`); non-markup array paths re-send only queued elements (`itemNeedsTranslation`); markup arrays stay whole-document.

**A `@Concept` link is masked as `⟦n⟧` while translated, and the restore must be forgiving.** A model doesn't always hand the placeholder back verbatim — transliterates digits (`⟦೦⟧`), pads, swaps brackets — and `\d` under `/u` matches only ASCII 0-9. `LinkMaskPattern` now accepts `\p{Nd}` digits, surrounding space, look-alike brackets, and normalizes digits ([protect.ts](src/util/verify-locales/protect.ts)); ASCII `[…]` is excluded (real markup uses it, `$value[true|false]`). `hasResidualLinkMask` refuses any translation still carrying a placeholder — `mismatchedConceptLinks` can't catch it when source has no links and both sides count zero.

**A translation run checkpoints, and `$~` is what makes the checkpoint durable.** A new locale is ~1.5 hours and ~$3, and used to reach disk once. `translateLocale` now takes a `checkpoint` callback per phase and per `CHECKPOINT_PATHS`-sized slice. Resume is automatic: `shouldStringBeMachineTranslated` already skips `$~` outside override. Load-bearing:
- Slicing is safe because slices *partition* paths: `indicesFor` memoizes per path, first answer wins — a path in two slices would send one set of elements and write back another.
- Slicing would otherwise cost money: `translateDeduped` dedupes within one request; `translateMemoized` ([ClaudeTranslator.ts](src/util/verify-locales/ClaudeTranslator.ts)) remembers across requests, keyed on system prompt + model.
- `writeFormatted` writes through a temp file and renames — a kill mid-write would truncate JSON.
- The new-locale branch in `start.ts` tests the locale *file*, not its folder (folder is created before translation; empty folder made the branch skip).
- Resume is cheap for `$?` work but not `$!`: paths in `revisedStrings` re-translate unconditionally.

**A failed re-translation must keep the translation it had.** `translateLocale`'s failure path used to write the en-US source marked `$?` — right for a never-translated string, destructive for one being re-translated. `keepOrPlacehold` ([verifyLocale.ts](src/util/verify-locales/verifyLocale.ts)) keeps a non-empty existing translation and re-queues `$!`; only a string with nothing to keep becomes `$?` + English. Any fallback writer must make the same distinction.

**A string has exactly one write-status.** `isRevised` tests `startsWith('$!')`, so `$~$!…` reads as merely machine translated. `checkStringArrays` normalizes markup arrays; [checkAnnotations.ts](src/util/verify-locales/checkAnnotations.ts) does the same for scalar strings, collapsing to highest-priority (`$?` > `$!` > `$~`). Never prepend a marker to a value that may already have one.

**Tutorial dialog is held to the same delimiter rule as locale docs.** `findDialogDelimiterProblems` ([verifyTutorial.ts](src/util/verify-locales/verifyTutorial.ts)) compares each dialog line's `\…\` and `` `…` `` counts against aligned en-US. Orphaned delimiter (source count even, translation odd) and unclosed literal (caught by `unclosedInCode`) are hard errors unless queued (`$?`/`$!`); `locales-fix`/`locales-translate` mark `$!` so the same run repairs them. Everything else is drift, gated on `DelimiterDriftIsFatal = true`. Requires the parity *flip*, not any mismatch — en-US ships one unclosed example, so a locale that fixed it is an improvement. Lines whose paragraph count differs are skipped (that is `syncTutorialStructure`'s job).

**A tour is named in one place, stepped in another, and the split is a budget (#984).** Interface tours are named in [tours.ts](src/components/project/tours.ts) and stepped in [tourSteps.ts](src/components/project/tourSteps.ts), so a lesson can point at one with `@Tour/<id>` markup. Load-bearing:
- `tours.ts` has no runtime imports — `ConceptLink` imports `isTourID` and the parser must never reach into components. Steps live elsewhere so seven kilobytes of explanation don't leak into every page (see [importGraph.test.ts](src/util/importGraph.test.ts)).
- A `@Tour/` naming a missing tour is a conflict (unlike `@username/character`, unknowable at check time).
- Request travels through a context slot, not a launcher function — tutorial dialog is a *sibling* of ProjectView, so `TutorialView` sets the slot above both.
- A step's `uiid` is unverified — a renamed target renders "not visible" indistinguishably from off-screen — so [tours.test.ts](src/components/project/tours.test.ts) sweeps for every step's target and every `@Tour/` reference.

**The tutorial's next control is held until a pointed-to tour is taken.** `TutorialView` derives pending tours from the same markup scan that produces `@UI/` highlights; a tour counts taken when closed anywhere (including the tile's ⓘ), recorded in the cloud-synced [ToursSetting](src/db/settings/ToursSetting.ts). Consequences:
- Skip control sits under the dialog (the nav row is a fixed three-part layout with no room).
- Refusal is announced (`tutorial-tour`, `interrupt` lane) — silence reads as broken. Interrupt is the only lane that re-presents identical text (the usual "vary text" rule can't apply — the refusal is the same event).
- When the gate lifts, `TutorialView` takes focus back — a pointer-opened tour leaves focus on the body.

**A locale tag may be written by name, and a code always wins (#1220).** `/es`, `/Español`, `/Spanish` are one tag; `/es-MX`, `/es-México`, `/es-Mexico` are one. [tagNames.ts](src/locale/tagNames.ts) is the one decider: `foldTagName` strips case, accents, non-alphanumerics. Load-bearing:
- Fold is locale-independent (plain `toLowerCase`, never `toLocaleLowerCase(reader)`) — programs must mean the same to everyone (see [casing.ts](src/unicode/casing.ts)).
- A code is matched before any name; a name that folds onto a different entry's code is never indexed (Sichuan Yi/Ho/Lü fold onto `yi`/`ho`/`lu`; Ho is writable only as `/hoc`, asserted in `tagNames.test.ts`).
- Source keeps the spelling the author chose; only `Language`'s accessors resolve.
- `getTagString`/`getBCP47` are resolve-or-raw, never strictly resolved: `TextValue` asks `getTagString() !== undefined` to know a value carries a tag; filtering would silently untag `'hi'/aaa`.
- Completing a tag as it is typed is a separate mechanism: `Language.getPossibleCompletions(anchor, edit)` is dispatched from two places in [PossibleEdits.ts](src/edit/menu/PossibleEdits.ts) (token-anchored branch in `getRelativeFieldEdits`, early return in `getFieldAssignments` for blocks). Keyed on the anchor token; `fieldIsEmpty` is *not* the lever. Completions must resolve back to the code offered for (offering Sichuan Yi's "Yi" would insert Yiddish).
- Ambiguity tests in [tagNames.test.ts](src/locale/tagNames.test.ts) block newly added names that would shadow existing ones.

**Region names are generated, never hand-edited.** [Regions.ts](src/locale/Regions.ts) stays hand-authored ISO 3166 — anchors `RegionCode`, `en` values deliberately tuned (`GB` → "UK"). [regionNames.generated.ts](src/locale/regionNames.generated.ts) adds each region's name in its own language, written by `npm run regions` from the pinned CLDR release. Ranking by CLDR population share alone picks *English* for Belgium/Ethiopia/South Africa (second-language speakers count), so official languages rank first; unfiltered ranking is a fallback. `de_facto_official` counts (Mexico Spanish, USA English); `official_regional` does not. Each entry records which language named it (BE→`nl`, CH→`de`, reviewable in the diff) plus CLDR's English name and alternates. AQ/HM fall back to English. [generateRegionNames.test.ts](src/util/verify-locales/generateRegionNames.test.ts) checks coverage, `RegionNamesCLDR === CLDR_VERSION` pin, and ranking against fixtures.

**Several locale artifacts are generated, never hand-edited**, and all hard-fail `npm run locales`: [static/locales/names.json](static/locales/names.json) (word→locale index for the languages dialog, built from each locale's basis); each locale's `<code>-how.json` bundle (from `how/*.txt`); `src/locale/choosePrompts.generated.ts` (first-run prompts); and `static/manifests/<code>.webmanifest` (one web app manifest per locale, so an installed Wordplay is named in the language it was installed from, #564). `npm run locales-fix` regenerates. The `unit / locales` CI job runs `npm ci` without a build, so nothing regenerates them there — a stale artifact is a red deploy. [localeArtifactsSync.test.ts](src/util/verify-locales/localeArtifactsSync.test.ts) runs the same checks in the `sweep` project; pre-commit runs the sweep when `static/locales/**` or `src/locale/en-US.json` is staged.

**The updates page is localized by content-addressing, so an entry is bought once and never re-bought (#1164).** CHANGELOG.md is authored in English and edited three times a day. [scripts/updates.ts](scripts/updates.ts) parses it into `static/updates.json` (release structure + emoji marker + entry Markdown converted to Wordplay markup) with stable ids `'e' + sha256(markdown).slice(0,12)`. A locale's translations are a bare `id → markup` map at `static/locales/<code>/<code>-updates.json` — structure stored once; missing id falls back to English per entry. That map *is* the incrementality. Load-bearing:
- Id hashes Markdown (not generated markup), so improving `toMarkup` doesn't invalidate every translation — `BundleFormat` is the lever when you do want that.
- Id never starts with a digit: `parseOverrideKey` reads a trailing all-digit segment as an array index.
- Only dated releases are translated (legacy `## 0.16.38` headings excluded).
- `toMarkup` runs at build time so translator markup validators apply to what the page shows.
- Bundle is fetched, not statically imported (was rendering into all 32 prerendered copies of the page, 450KB each).
- A translation is refused unless it parses as markup across its whole length (via `checkHowToBody`) — length comparison, not exact round trip.

**A changelog entry's code is syntax being described, and only its names may be localized.** `translate()` localizes embedded `\code\` examples, which is right for renaming (German `Rede()` not `Speech()`) and wrong for everything else. Changelog entries about syntax lost their examples (German `'hallo'` shipped three times, Persian `fa-AF` → `fa - AF`). [restoreExampleSyntax.ts](src/util/verify-locales/restoreExampleSyntax.ts) decides per span by *token shape with names blanked and spacing kept*: same shape means only names changed; anything else restores from English. Spacing is in the shape (`fa-AF` and `fa - AF` tokenize identically). Runs before storing each translation and again over disk under `locales-fix`.

**The archive was condensed once, deliberately, and the rules that did it are kept.** [condenseRules.ts](scripts/condenseRules.ts) refuses a rewrite that drops a `` `code` `` span, a link, or a `(#N)` citation (multiset compared) — those are the only parts of an entry a reader can act on. The model must *declare* what it removed and name a reason for a second sentence. [changelogStructure.test.ts](src/util/verify-locales/changelogStructure.test.ts) is the gate CHANGELOG.md never had — it's in no pre-commit trigger and `verifyChangelog`'s markup check only runs under `npm run locales` against a gitignored artifact.

**A `<label@url>` target was the one construct reaching a translator unprotected.** `ConceptRegExPattern` refuses `@` before `http://`/`https://`/`mailto:`, so `protectConceptLinks` masked `@Concept` and nothing masked URLs; no validator checked one came back. `protectLinks` ([protect.ts](src/util/verify-locales/protect.ts)) masks both; `mismatchedWebLinks` refuses drops/inventions/rewrites. Ordering rules:
- Targets are masked *before* concept links — `ConceptPattern` is the raw pattern without the tokenizer's email-boundary rule and would otherwise eat `@x.dev` from `<Email us@mailto:hi@x.dev>`.
- The concept pass skips a match containing the mask delimiter (a Wordplay name may be almost any character, so `@⟦0⟧` lexes as a concept link).
- An issue link is masked whole (its label is the issue number; digits get transliterated).
- Other labels stay visible — translating "About" to "Acerca de" is the point.

**Installability is manifest-only — there is deliberately no service worker.** Add-to-Home-Screen / Add-to-Dock need no service worker, and data is already local-first (`WordplayDexie`; see [firebase.ts](src/db/firebase.ts)). Installing matters because WebKit deletes script-written storage after 7 days without interaction and exempts home-screen web apps — installing is the only protection for a signed-out creator's local projects. Offline cold-start is the one thing a SW would add; not worth a second update path beside the version poll + [UpdateNotification.svelte](src/components/app/UpdateNotification.svelte), nor a cache policy per asset kind (`static/` is 223MB vs 7.4MB shell). Two consequences handled explicitly: iOS installed-app storage is a container separate from Safari's, so [installedStorage.ts](src/routes/[[locale]]/projects/installedStorage.ts) gates an explanation for signed-out/empty; and an emailed sign-in link opens in the browser rather than the installed app, so [Login.svelte](src/routes/[[locale]]/login/Login.svelte) accepts a *pasted* link.

**Moderation is server-authoritative, and the ban is a claim, not a read.** A creator's moderation record lives at `strikes/{uid}` — server-written, client-readable, exactly the `usage/{uid}` pattern, never on `creators/{uid}` (client overwrites wholesale). Reports live in a `reports` collection (a non-contributor viewer can't write the project document). Everything a moderator's decision does happens in the `moderateProject` callable ([functions/src/moderateProject.ts](functions/src/moderateProject.ts)): flags, un-publishing, resolving reports, strike count, and at the third strike the `banned` custom claim + taking down existing published content. `firestore.rules` enforces the ban through the claim alone (`mayBePublic()`) — reading `strikes/{uid}` would cost a document read on every project write. Consequences:
- A function that sets claims must *spread* existing ones (`setCustomUserClaims` replaces the whole object; writing `{banned:true}` alone strips `mod`/`teacher`). [scripts/claims.js](scripts/claims.js) does this.
- A claim only reaches a session on token refresh, so the client watches its own record and calls `getIdToken(true)` when it changes.

**A character is in at most one gallery, and the rules are why (#822).** A gallery holds characters as well as projects — not a second parallel kind. `Character.gallery` is the source of truth; `Gallery.characters` is the index built from it, both written in one batch. The gallery page renders from the character side so a share appears without waiting for the gallery doc. One-gallery isn't a preference: security rules have no loop, so several would need a server-maintained flat viewer list rebuilt on every membership change (one costs a single `get()`, ordered *after* owner/collaborator/mod so only paid when nothing cheaper allowed the read). Asymmetries:
- A public gallery grants read to a signed-out visitor, one step further than `canReadProject`'s gallery grant (which is inside its auth guard).
- A curator cannot edit a character in their gallery, though they can edit a project there — sharing a drawing isn't handing it over; the remedy is removal.
- A remix carries no gallery, like a remixed project.
- `CharactersDatabase` streams gallery-mates' characters via chunked `where('gallery','in',...)` (same `GALLERY_CHUNK_SIZE`), removal decided against the *union* of every listener — a character leaving the gallery query is still yours.
- Reads are no longer gated on being signed in (#742): rules always allowed a public character; the guard was blanking public projects for visitors.

**A creator's character names must be unique, and only the name is held back.** Uniqueness is on the *full* `username/Name` among characters you *own* — that is what `byName` and the `where('name','==',…)` lookup key on. Two creators naming one `Dog` collide with nothing; one creator doing so makes `@them/Dog` resolve to whichever the query returns last. The check it replaced compared bare names across everything you could edit, so collaborating on `bob/Dog` reported `Dog` as taken. Not enforced through `savable` — that would stop saving *shapes* too, silently losing every stroke drawn after a colliding name is typed. Only `editedCharacter`'s `name` falls back to `persisted.name`. E2e tests sharing one account must give characters distinct names.

**Folders are split across two documents on purpose.** Membership (`Project.folder`) is on the project doc so it merges per-field across devices; folder name + collapsed state are creator settings, so renaming is a single write rather than a rewrite per project. The halves sync independently — `resolveFolders` puts a project whose folder hasn't arrived yet at the top level rather than hiding it. Anything added to `SettingsSchema` must land with its `syncUser` read *and* its `toObject` write in the same change, or the next write of any other setting drops it.

**A bare email address in markup is a link.** `hi@wordplay.dev` lexes as one `Sym.URL` and renders as `mailto:`; `<Email us@mailto:hi@x.dev>` works too. `ConceptRegExPattern` refuses `@` directly following an email local part and exempts `mailto:` the way it exempted `http://`; the markup tokenizer looks ahead for an address and cuts the preceding words run at its local part. Every URL-token → `href` goes through [linkHref.ts](src/parser/linkHref.ts), which allowlists schemes — a `javascript:` URL must never become an anchor.

**The translation cap lives at the callable, not the feature.** `getLLMTranslations` bills per call, requires a signed-in caller, and reserves characters against `usage/{uid}` before the model runs ([translationBudget.ts](functions/src/translationBudget.ts), `DAILY_TRANSLATION_CHARACTERS`; client mirrors the number for display only, [translationBudgetSync.test.ts](src/db/translationBudgetSync.test.ts) fails on drift). Anything new that translates should go through [getFirebaseTranslator](src/db/getFirebaseTranslator.ts) and drop in `TranslationMeter`. Never put a counter on `creators/{uid}` — client-writable, overwritten wholesale by `uploadSettings`.

**Text that becomes code must not be translated.** A creator's `key = 'ArrowLeft'`, map key, or emoji literal is data — giving it a target-language option changes what the program does (#1276, same rule as #1228). [translatableText.ts](src/db/projects/translatableText.ts) is the single decider; extend it rather than adding call-site checks. Adding a translation must not rewrite the program: the `replace` flag gates all reference/`NameType`/`Input` retargeting, and adding a name appends rather than calling `Names.withName` (which replaces an untagged name). Retargeting always asks for a non-symbolic name (locale first name is often an emoji). A guard for code must not run over prose: `translationProblem` checks only inside `\code\`. Two non-obvious renaming reaches (regression-tested in [translateStructures.test.ts](src/db/projects/translateStructures.test.ts)): a `NameType` (`zombie•Zombie`) names its definition but is not a `Reference`; and a translated name must avoid the *target locale's* basis names as well as the project's own.

**A kit is one published source, and immutability is what makes borrowing it cheap (#8).** `↓ @amy/colors 3` names a kit — owner-scoped, `@`-prefixed (else ambiguous with a borrow of an English source), versioned by the numeral `BORROW` already parsed. Every borrow funnels through `Project.getShare`; kits are a third tier below sources and basis. Borrow resolution is synchronous — analysis and evaluation both resolve without awaiting — so a kit is fetched and parsed into a `Source` *before* the `Project` is built (`resolveKits` → `withDependencies`). Deliberately unlike `@username/Character`, which resolves async in a component and degrades to an empty box. Load-bearing:
- Schema is split: `kits/{id}` (small mutable registry) + `kitversions/{id}_{n}` (code, immutable). A version is cached in IndexedDB permanently and never invalidated; `public` and `owner` denormalized; read rule is a field test with zero `get()`s. Keeps borrows off the rules' ~10-doc budget (behind `GALLERY_CHUNK_SIZE = 8`) — a class of thirty sharing one kit costs thirty reads *ever*.
- No listeners on a consumed kit.
- Two `public` flags do different jobs — `kit.public` governs discovery, `version.public` governs resolution. Only moderation clears versions; `applyRemedy` must clear both in the same batch.
- Conversions can't travel by name (`Convert` matches types, `ConversionDefinition` isn't in `Definition`), so `↑` conversions become ambient in whatever source borrows the kit; gating on the borrow is what stops them leaking.
- Imports are flat; namespacing them is #1373. Materializing a kit as a `StructureDefinition` with statics fails (`isStatic` is `Bind`/`FunctionDefinition` only; `↑ •Inner()` inside a structure parses cleanly and does nothing).
- Kit database is dynamically imported (`DB.loadKits()`) — eager wiring put it on all five page graphs.
- A new sync domain must report itself settled (`Kits` in `SyncDomains` needs a `startSync` arm), else the save-status footer spins forever.

**Three kits ship with Wordplay, as files rather than documents.** `@wordplay/alphabets`, `@wordplay/instruments`, `@wordplay/tunes` live at `src/db/kits/sources/<name>/<version>.wp`, listed by a literal in [builtins.ts](src/db/kits/builtins.ts), and built into registry entries in memory (like `getExampleGalleries`). Sources are *imported*, not fetched (`UnknownKit` on load failure would break someone's *own* project) — hence `src/` rather than `static/`: `?raw` inlines them into the `loadKits` chunk. Seeding `byName`/`versions` first means a cloud kit can never shadow a built-in by name; `seedBuiltins` must re-run at the end of `clear()`. A built-in is never persisted to Dexie. A shipped version's file is never edited; an improvement is a new file. Shipping through git *is* the moderation decision; `builtinKits.test.ts` is the moderator. Two rules govern examples and types:
- **`ExampleScope` context**: a kit's page reported `FunctionException` on its own docs because `ExampleUI` built self-contained projects. `KitView` now supplies a prelude (`↓ @owner/name version`) + resolved dependency; the prelude is prepended to the example *and shown with it* (part of what a reader copies). Exposed via a getter, never assigned in an effect (a kit loads async; an effect sets it after examples have mounted).
- **`Block.getStatementIndexContaining` must use `context.getRoot(node) ?? context.source.root`**: a node inside a borrowed kit has a root in `project.roots` but not `getSources()`, so `context.source.root` failed silently and `.method()` calls halted with `FunctionException` at compile time. Follow `typeGuards.ts`.

**A kit is localized in place, and four rules make that possible.** A per-locale copy isn't expressible (a kit is referenced by name and stores one `code`); every language lives in the one source (`↑ latin/en,latín/es`, `¶…¶/es` per doc). [verifyKits.ts](src/util/verify-locales/verifyKits.ts) drives `translateProjectContent`'s **add** mode (appends, skips already-tagged, re-running is free). Rules:
- Data literals are tagged with the language they *are* and `preserveTagged` keeps them verbatim.
- `translateTaggedNames` is needed because `MissingShareLanguages` forces export names to be tagged too — tagged-ness cannot also mean "don't translate".
- `examples: false` — a backend localizes an embedded example by building a project from it alone, where a kit's definitions resolve to nothing.
- Names inside docs are skipped in add mode — else throwaway lambda parameters collect an alias per locale.

Two general bugs fell out: `p.toWordplay()` with no `Spaces` stripped every space from embedded examples; a shared definition's `↑` was stranded on its own line when re-spaced (`Bind`/`FunctionDefinition`/`StructureDefinition` now keep the marker with what it marks). Since `.wp` carries no write status, naming a kit under `override` strips that language and lets add mode replace it. Kits are the one content `batch.ts` must not parallelize — `splitKitPhase` pulls it out of the parallel phase.

**What a published kit owes its readers is a conflict on the code, not a checklist in a dialog.** `UndocumentedShare`/`UnexampledShare` sit on each `↑` definition, `UnexampledKit` on the `Program` when no `\…\` example exists, and `KitCannotBorrow` on `↓` — all `Minor` (the code runs fine; `Error` would block blocks-mode edits). All four fire only in a source a project *publishes*. One implementation ([publishedShare.ts](src/nodes/publishedShare.ts)) is asked two ways: through `computeConflicts` and hypothetically by `checkKit` for the publish dialog — without which the first publish is ungated and every one after is gated. The dialog renders those conflicts' own explanations. Load-bearing:
- A project publishes at most one kit, recording the kit's *id* (`Project.getKitID`, schema v12), not its name — a name lookup after rename made the first publish silently create a second kit. `changeUsername` rewrites kits like characters; `aliases` is server-owned.
- A kit's description is derived (first sentence of source doc); preview is the `⭐` example rendered once at publish and cached on the version, evaluated in the kit's own scope — `kitPreviewSource` appends it to the kit's code.
- Kit page is `/guide?kit=amy/colors`, its own URL param because `?concept=` splits on `/` (owner + name). Rendered via `kitShareConcepts` through the docs-tile views.
- #1374 hoists a source's leading doc onto the *program*, so the first definition can't be documented — `docsFor` falls back to program docs (publish dialog and `UndocumentedShare` accept it; the kit page still reports it). Scoping half of #1374 is fixed: `Program.getScopeOfChild` scopes docs to itself.
- `makeKit`'s output is held against `kitServerFieldsInitial()` by `rulesFieldsSync.test.ts` — the create-time guard galleries lacked (#1352). Client never writes `moderation`; the `kitEdited` trigger answers.

### Dependency overrides

`package.json` is JSON, so overrides can't carry comments. Rationale lives here.

**`cookie: ^0.7.0` must not move past `^0.7`.** Patches CVE-2024-47764 (cookie <0.7.0); `npm audit` is clean at 0.7.2. SvelteKit imports `{ parse, serialize }` and `CookieSerializeOptions`; cookie 1.x renamed the type and 2.x removed both functions. Bumping has no security upside and breaks Kit. Revisit only when SvelteKit's own `cookie` range moves.

### Immutability convention

Immutable data structures and pure functions are the norm everywhere except: Svelte components (internal state + global context), `Evaluator` (stack-based state), `Database` (persistence). Most bugs will be there.

**Adapting project output to a dark canvas is one decision per stage, not one per color.** A dark-mode viewer can flip a bright stage dark (`adaptOutput`); the transform is an LCh **lightness inversion** — `L → 1 − L`, hue/chroma untouched ([adapt.ts](src/output/Color/adapt.ts)). Not a hue complement (changes color identity, doesn't darken) and not dimming (loses WCAG AA on 20% of pairs). Inversion preserves every pair's |ΔL\*| exactly and is an exact involution, which lets [PhotosensitivityAnalysis](src/output/PhotosensitivityAnalysis.ts) keep measuring authored values. Because contrast is a relationship, adapting some colors and not others destroys it, so:
- The flag rides on `RenderContext` and `getColorCSS` *requires* it (a call site can't silently forget).
- The decision is latched per `Evaluator` in `OutputView` — an animated background can't flip the palette mid-run. A revision (new `Evaluator`) re-decides so palette editing stays live.
- `OutputAnimation` applies it to WAAPI keyframes (which never pass through Svelte markup).
- Fires only above `AdaptationLightnessThreshold = 0.8`, not 0.5 — WCAG's ratio isn't symmetric about mid lightness, and a mid-toned stage isn't the blinding rectangle the feature exists for.
- Persisted project previews ([extractPreview.ts](src/components/app/extractPreview.ts) writes CSS *strings*) are adapted at render ([adaptPreview.ts](src/components/app/adaptPreview.ts)), never at extract, or one viewer's setting ships to everyone. Path parses `lch()` with a regex, not `ColorJS` (blew the [import budget](src/util/importGraph.test.ts)).
- Music renderings (`LightShow`, `Mood`) are excluded — they hold lightness/opacity constant as their flash-safety invariant.
- Every output surface declares the `color-scheme` it *actually paints*, not pinned `light`, so theme-token fallbacks resolve against the creator's background.

**Markup is edited as a `Source`, and prose mode is a rendering rather than a preview (#1307).** The markup editor wraps a string in the doc delimiter — `markupToSource` in [markupSource.ts](src/edit/markup/markupSource.ts) — so `Caret`, `RootView`, `CaretView`, keyboard mirror, IME, and announcer all apply unchanged; embedded code needs no second mechanism. Wrapper is **unconditional**, unlike `toMarkup`'s "skip if starts with `¶`" — an editor that lost text to it would lose the creator's work. Load-bearing:
- `text` is written back only from `apply`, never on mount.
- Prose mode hides delimiters through `RootView`'s existing hidden-node set — a hidden token keeps its DOM place at zero size with `aria-hidden`, and the caret can still land on it. Reveals the run the caret is inside.
- Command list order: markup-first, then borrowed code-editor motion/deletion, typing catch-all last (`handleKeyCommand` takes first match).
- `handleInput` must *return* after clearing `skipNextInput`, or the command and browser field-edit both apply (every character typed twice).
- Editor must never reach a page's static import graph: `FormattedEditor` is rendered by `MarkupHTMLView` on every page, so it imports the editor **dynamically** and renders the toolbar from *inside* — a static import of the command list puts the whole language runtime on all five page graphs (see [importGraph.test.ts](src/util/importGraph.test.ts)).

**Markup has no aside, and a `¶` used as one silently truncates the document.** `toMarkup` wraps a body in `¶…¶`, so an author's `¶` closes that wrapper and everything after parses as code — unrendered, invisible to `npm run locales`. Same for a lone `` ` `` (opens formatted literal) or odd `\`. `checkHowToBody` ([buildHowTos.ts](src/util/verify-locales/buildHowTos.ts)) fails a body whose parse doesn't cover it. An aside is written as an ordinary paragraph; a literal backtick is doubled. Shape trap when repairing: a `¶…¶` immediately after a `\` on its own line is a doc on the code *inside* an example and legitimate (`choose-adventure`, `layering-images`); only `¶` outside an example is the bug. Damaged translations rebuilt in #547; example-names-sync exemption removed.

**Soft wrap has to reach the renderer, not just the CSS.** The editor renders every space as U+00A0 so a line holds its shape while edited; `RootView`'s `wrap` prop turns that off. `Editor.svelte` set the `.wrap` class but never passed the prop, so spaces stayed non-breaking and long tokens never wrapped. Passing it is the whole fix. The context also had to become a **store** — held as a plain boolean, it froze at mount. Residual to know: after toggle the virtualized scroll extent stays stale until the next keystroke, though text wraps immediately.

**Prose mode is a rendering of the same tokens, so what makes it prose is CSS that lives where the code styling does.** Code font is re-asserted per token by `.token-view`; `TokenCategories` maps `Sym.Words` to *literal*, so a markup editor rendered through `RootView` shows every word in the code font and literal color. `format.prose` is threaded through `Format`. Load-bearing:
- A token must be `display: inline` in the markup editor, both modes — the tokenizer emits one `Sym.Words` per run, so a paragraph is often one token; `inline-block` is atomic and can't split (a paragraph following a bold run moved to the next line whole).
- A hidden delimiter must stay `inline-block` — `.hide` collapses via zeroed width/height, which don't apply to an inline (making tokens inline is what made prose mode show every `*` it was supposed to hide).
- An `Example`'s program is rendered with `prose: false` (`ExampleView`), so code inside prose keeps its font and syntax colors.

**Per-token state belongs on `Format`, not in a context.** Anything a token reads on each render is a per-token multiplier. Soft wrap needs to be reactive (setting toggled while the editor is open), but making the context a store gave every token a subscription (+5% typing cost). `Format` is already threaded and recreated per render, so carrying `wrapping` there is reactive and free. Same rule as `CaretTokenSummary`: resolve once in the editor, hand tokens a value.

**Two editors share a spine, and the input layer is where they can rot.** `Caret`, `RootView`, `CaretView`, `PointerUtilities`, `Highlight`, and the `Command` apparatus are single implementations both editors use; `Editor.svelte` is full, `MarkupEditor.svelte` restricted. The ~150-line input layer is *duplicated* because the two genuinely differ (markup offsets by its `¶` wrapper, no blocks, own history, no internal clipboard). Three shipped fixes extracted as *rules* rather than left in two copies: `shouldEchoNatively` (#1248), `caretFieldSelection` (#1329), `isComposingKeyDown` (#1054). Coverage keeps the glue honest, not `KEEP IN SYNC` markers: [ime-composition.spec.ts](tests/end2end/ime-composition.spec.ts) runs Latin/Korean/Japanese/stuck composition against **both** editors — a bare `querySelector('textarea.keyboard-input')` finds the code editor's, since ProjectView mounts both.

**An editor is more than a caret model.** First-pass markup editor gaps were host-declaration issues, not architectural:
- Hidden mirror needs `pointer-events: none` — else `elementFromPoint` returns the textarea and no click can place the caret.
- Container needs `isolation: isolate` — else a selection highlight's `z-index: -1` escapes and paints behind the host's background.
- Container needs a `line-height` — a token's box is its line box, and inheriting a prose host's line-height made the caret paragraph-tall.
- Vertical-movement commands need `view` and `getTokenViews` on `CommandContext` — else they `return false` and `handleKeyCommand` keeps scanning.
- `CaretView` reads the singular `setEditor` context to know it is focused; with only `setEditors` (plural), the caret renders permanently at `opacity: 0.25`.
- `outline.ts` finds an outline's origin with `closest('.editor, .markup-editor')` — a host that matches neither gets viewport coordinates inside a relatively-positioned box.

**A token's box is the union of every line it covers, and in prose a token is a paragraph.** Nine defects were one: caret placement, selection outlines, pointer hit-testing, and vertical motion all measured with `getBoundingClientRect`. `getClientRects()` gives per-line-fragment rects (exactly one for a non-wrapped token), so the fix is shared and unconditional (code is byte-identical; soft-wrapped code fixed too). [measureTokenSegment.ts](src/components/editor/highlights/measureTokenSegment.ts) grew `segmentLineRects` and `graphemeOffsetAt` (binary search over collapsed-range positions, block axis first). Notes:
- The search hoists tree walk + grapheme segmentation out of the loop — `locateCaretRect` did both per call. Shared `graphemeTable` cuts +40% to +11%; typing is unaffected.
- `CaretView`'s `lineHeight` fallback was the union box *and cached*; the first token measured poisoned every later caret. The `<br>` probe never matches in text mode (`NodeView` renders the break in the sibling `.space` span).
- End-of-document caret resolves to the `¶` wrapper, never rendered, so it re-anchors to the previous token — union-box put it at the first line's far edge. `edgeOfToken` measures the last line's rect from a *non-collapsed* range (Chromium reports no rects for a collapsed range at end of a text node).
- `outline.ts` had two `closest('.editor')` lookups that are `null` in the markup editor, so inter-paragraph whitespace was silently dropped from every selection.

**A caret is not a selection, and both have to survive an edit.** Three causes made a selection look broken. Outline traced in a `$derived` runs *before* Svelte commits DOM — resolves nodes by id, and an edit gives every node a new id. Now `$effect` + `tick()`, as `Editor.svelte`'s search outlines already were. `Caret.isIn` returned `false` for every range, collapsing every reveal on selection (`*…*` re-hid itself, web link snapped back to anchor); a range is now "in" a node when the node contains both ends. `Caret.delete`'s range branch returns `[newSource, caretOnOldSource]`, and `apply` read only the caret's source — Backspace on a range moved the caret and changed nothing. Anything applying a borrowed command's `[Source, Caret]` must take source from the tuple.

**Word motion did not exist anywhere in the app, and `pointerdown` carries no click count.** The code editor's arrows step *token* boundaries. `moveByWord`/`wordAt` build on [getWordInfo](src/runtime/pattern/segment.ts), which wraps `Intl.Segmenter`, degrades malformed tags, and returns boundaries in *grapheme* indices (the unit `Caret.position` counts in). Forward → end of next word; backward → start of previous, skipping punctuation. Bound to Alt/Option+Arrow; Control/Command+Arrow takes line boundary. Not for the affordance but because an unmatched chord bubbles out and `Control+ArrowLeft` is the timeline's step (same defect as `Control+Home`). Double/triple-click count their own clicks: `detail` is a MouseEvent notion `pointerdown` reports as 0 in Chromium, and where populated it continues *that platform's* click chain — trusting it made a double-click after an earlier caret-placing click select the paragraph.

**A caret at the end of a paragraph is a caret in the space, not in a token.** The `\n` between paragraphs is *space*, so that caret takes `CaretView`'s space branch and anchored to `priorTokenBox.inlineEnd` — the union box again. `edgeOfToken` gives the prior token's last-line end instead. Different branch from end-of-document, same cause.

**A link that isn't an anchor still has to look like a link.** Dropping `<a>` in prose (had to go — swallowed the `pointerdown` that places the caret, was a Tab stop in `role="application"`) left links looking like ordinary text. Both now carry link color + underline without being anchors: `WebLinkView` styles its whole run (delimiters included); `TokenView` marks bare URL/email `link`. Two rules:
- Styling must out-specify prose neutralization (attribute selector `[class*='token-category-']`).
- Splitting "is a URL" from "renders as an anchor" is what makes bare-email work: `linkedURL` consulted `$caret`, which `MarkupEditor` never provides — every `TokenView` would subscribe — so email was *permanently* an anchor.

**An empty document renders nothing, so the caret had nothing to anchor to.** Every branch of `CaretView.computePlacement` resolves a token view; empty markup has none. `atContentStart` places it at the content's start. Gated on `getTokenViews().length === 0`, not on a token view being missing — a token scrolled out of virtualization also has no view, and the windowing code depends on getting no placement so it can scroll the caret in.

**The mode switch is a toggle, because it has two states and a button shows neither.** `ui.markup.mode` already had the two `ToggleText` strings; the tip names the action from whichever mode you're in. Routes through the same `onToggleMode` the mode *command* calls, so button and Control+Enter can't disagree; `aria-pressed` tracks either. `CaretView` takes `prose` as a **reflow signal** — not a setting it reads, a statement that showing/hiding delimiters moves geometry.

**Tab always leaves the markup editor.** An unmatched keystroke has its default prevented (so browser can't edit the mirror behind the model's back), and Tab was caught by that. `role="application"` offers no other way out, so consuming it is a keyboard trap — and prose has no use for an inserted tab worth trading that for.

**A link with no URL is not a link.** `insertWebLink` used to splice `<label@>`, and a `Sym.URL` needs `://` and a character after — that isn't a `WebLink`, it's prose that renders its own brackets, and the next `@h` lexes as a concept reference. Now inserts IANA's reserved `https://example.com` with the URL selected, so it parses from creation and typing replaces it. `markupHidden.ts` hides everything but the description and reveals it at the caret (bold/italic already follow this).

**`Source.reparse`'s fast path could silently swallow a typed character, and the reason is still unknown.** `tryTextOnlyEdit` handles one-token text changes with no boundary moves by replacing that token. When the replacement doesn't land, the tree comes back unchanged; because `Source.code` is regenerated from the AST, the character never appears (typing a URL into a markup link dropped every letter after the first). Reproduces only in the browser, not vitest with the same edits — token list + leaves are the same instances in the same order, so `replace` finding nothing is unexplained. The guard is right regardless: verify the edit landed, fall through to full reparse.

**Example annotations apply next to an example, not only inside it.** `enclosingExample` asked `getTokenAt(span[0])` with `position < index + length`, so a caret one past the closing `\` resolved to prose *after* the example — where `⭐` and `🪲` are rendered. The token *ending* at the position counts too (the ordinary adjacency rule).

**The markup toolbar's groups are the command list.** [MarkupToolbarGroups](src/components/editor/markup/MarkupCommands.ts) is the single source of order for toolbar + keyboard (safe because no two markup commands share a shortcut, asserted). Undo/redo lead; the example insert sits with the annotations it produces. Those four annotations are **hidden** outside an example rather than greyed (four permanently grey buttons read as broken), but remain `active`-gated so the shortcut is still consumed and explained. Visibility is decided from a *debounced settled caret* — the caret publishes on every keystroke, and a toolbar whose item count changes that often makes `OverflowToolbar` re-measure everything. Group separator is [Separator.svelte](src/components/project/Separator.svelte), inside the first item of each group (measured with it) and hidden in the overflow panel.

**Prose motion is not code motion, and an unmatched keystroke is not harmless.** Four defects only appeared when a whole multi-paragraph passage was written end-to-end:
- **Arrows must move by character**: the code editor's `moveInlineText` selects the *node* — right for a subexpression, bewildering in a paragraph. The `¶` wrapper makes the end of text a token boundary always, so ArrowLeft from the end selected the whole sentence. `moveByCharacter` ([formatOperations.ts](src/edit/markup/formatOperations.ts)) replaces those four commands; must come *before* borrowed ones in the dispatch list. Ranges are `[anchor, focus]` and may descend (normalized by `spanOf`, `caretFieldSelection`, `getRangeOutline`).
- **Unmatched chords bubble by design** — that is how app-global shortcuts keep working. `Control+Home` is the timeline's step-to-beginning, which stepped the evaluator, remounted the chat composer, and discarded the message being written. Bind Control+Home/End here (reusing `sourceStart`/`sourceEnd`).
- **Enter must continue a bullet, ending the list on an empty one** — without it, a creator makes one bullet then invokes the command for every subsequent item. Ending the list must leave a *paragraph* break, or what comes next belongs to the last bullet. Declares `typing` for `InsertLine`'s reason; declines off a bulleted line so `InsertLine` still inserts an ordinary break.

**A soft-wrapped token's caret is measured, not computed.** `CaretView` placed the caret at the token box's inline start plus the width of a `Range` from the token's start — both union boxes, so as soon as a token wraps, the caret lands on the first line at the widest line's width. `locateCaretRect` asks for the collapsed caret position directly and takes the *last* rect returned: at a wrap boundary the browser returns two (end of one line, start of next), and a caret position is an index whose character *follows* it, so the caret belongs on that character's line.

**The editor's geometry is inline-axis geometry, and one projection carries every writing mode.** Caret placement, row clustering, selection outlines, and pointer hit-testing all read physical `.left/.top/.right/.bottom`, branching on an RTL flag beside a hard-coded `const horizontal = true`. [axes.ts](src/components/editor/util/axes.ts) replaces both: `Axes.rect`/`point` project viewport geometry onto a logical basis — `inline` along text, `block` across lines, both increasing in reading order in every mode — and `place`/`box`/`size` project back once, where CSS is emitted. Monotonicity lets `<`, `Math.min`, and sort comparators stay untouched; RTL stops being a separate mechanism. Consequences:
- `rowModel.ts` needed no algorithmic change — it was already this algorithm named physically.
- `CaretView.computeLocation`'s twelve `horizontal ? …` branches were deleted — their vertical arms added a height to an x-coordinate and had never run.
- `outline.ts`'s row tracer is pure geometry over rectangles, so `rowFrame` transposes in and out.
- **Arrow keys are remapped, not re-bound**: `remapArrowKey` translates a keystroke into the horizontal key with the same *meaning*, so every command keeps its behavior and its localized description; skips Control/Alt arrows (bound to evaluator stepping and literal incrementing).
- **Every projection over code comes from that code's own writing layout, never the reader's interface setting** — `CommandContext.writingLayout`, not `Settings.getWritingMode()`. The four visual line-move commands built from the interface's is the default pairing for a vertical Japanese source; failure was invisible (grouping glyphs *across* columns), reproducible only on WebKit's rounding, and would not have been caught by PRs (chromium-only).

**The editor's layout comes from the code, the interface's from the reader, and conflating them was the mistake.** A project written in Latin only makes sense horizontally whatever language the reader has. `eligibleWritingLayouts` ([src/edit/eligibleWritingLayouts.ts](src/edit/eligibleWritingLayouts.ts)) reads the source's *glyphs* and returns what it could be set in; the toolbar offers those and the creator picks, per project + source (`SourceWritingSetting`). Stored choice re-checked against eligibility on every edit — typing Latin into Japanese takes vertical away. Four traps (each with a regression test):
- `ƒ` and `ø` are Latin letters (Wordplay's own syntax) — scan only `Name`/`Words` tokens.
- A unit's `m` lexes as a `Name` — `Dimension` leaves skipped, or `1.5m` disqualifies every measuring program.
- `ー` is `Script=Common` — use `\p{scx=}`, not `\p{sc=}`, or `フレーズ` reports "not Katakana".
- ISO composite codes `Hans`/`Hant`/`Kore` are not Unicode script values — skip and resolve through `Hani`/`Hang`.

Signal is orthographic on purpose: `Project.getLocalesUsed()` misses untagged text, and a locale is not a script (Serbian is written in two alphabets).

**The writing layout is offered only where it means something, and `verticalLayout` is neither `layout` nor a boolean.** `layout` is a script's modern default (correctly `horizontal-tb` for CJK); `verticalLayout` names the one vertical mode that script is actually set in. Must be a layout, not a flag: CJK runs columns right-to-left, Mongolian left-to-right, no script uses both — a boolean would offer Japanese `vertical-lr`, which nothing they read is set in. Gate on `Locales.supportsVerticalLayout()` — true when *any* chosen locale qualifies, so English + Japanese still gets the choice. `resolveWritingLayout` returns `horizontal-tb` when gate is closed **without disturbing the stored value**, so removing/re-adding a locale toggles application while preserving choice. Reaches DOM as `data-writing-layout` on `<html>`; surfaces opt in via the global `reading-surface` class (setting `writing-mode` on `:root` would turn toolbars/tile manager/pickers sideways). Rules:
- **The line is between reading and operating**: markup declares no writing mode. Long-form reading surfaces declare it and markup inherits (concept docs, how-to answers, guide intro, lesson turns, static prose). Test is "would someone read this at length", not "is this prose" — a settings dialog is prose and is somewhere you operate.
- **Mark goes on each prose block**, never on a pane that also holds card listings — a grid inside a column is bounded by the column's width whatever its own writing mode.
- **A vertical block needs a measure, a bound, and its own scroller.** `reading-pane` supplies each: `inline-size: min(40em, 80dvh)` with `flex: none`; a bound on the other axis; own scroller (columns grow toward decreasing x, no LTR ancestor scrolls that way). Split load-bearing: `reading-surface` says "prose"; `reading-pane` says "and it fills the window" — false for a lesson's dialog.
- **Vertical text takes line length from block *height***, opposite of a stacked layout — the tutorial keeps side-by-side and only wraps prose in a `.lines` block (else `← title →` becomes a 1083px stack).
- Code inside vertical prose opts back out: `ExternalExampleView` declares `horizontal-tb`. `RootView`'s own `horizontal-tb` must be overridable because the editor renders through it — pass a `layout` prop; everywhere else leaves it undefined.
- **Surface is opt-in per page**, never on `Writing.svelte` (backs 18 routes — listings and forms should not be vertical). Six pages pass `reading`.
- Class is `reading-surface`, not `reading` — `Speech` uses `reading` positionally.
- Chrome nested inside a text surface must opt back out (editor search panel uses `align-self`/`order` and needs `horizontal-tb`).
- Output is *not* governed by this: `RenderContext.layout` comes from the *project* locale (a viewer can't re-lay-out someone else's composition). Vertical phrase uses its own `direction` (#220).
- Cost bearers: `Axes` carries scalar `blockStart`/`blockEnd`/`containsBlock` beside `rect` (pointer code tests every token view per drag frame, and projecting before filtering allocates); `eligibleWritingLayouts` is memoized on the immutable `Source`.
- `npm run rtl` guards two tiers — inline-axis properties everywhere, block/scroll-axis properties on `TEXT_SURFACES` — with `/* physical: reason */` comments; [logicalCssSync.test.ts](src/util/logicalCssSync.test.ts) runs it in `npm test`.

### Accessibility

### Screen-reader announcements

All dynamic announcements must go through [Announcer.svelte](src/components/project/Announcer.svelte), which owns the app's single live region. Do **not** add component-local `aria-live` divs — they conflict with the centralized region and cause cross-talk ([ariaLiveConvention.test.ts](src/util/ariaLiveConvention.test.ts) enforces this).

The Announcer owns **two** regions: an **immediate** (assertive) region for direct answers to keystrokes (typing echo, caret, rejected edits), holding nothing so each keystroke replaces the last; and a **paced** (`role="status"`, implicitly polite) region for everything else, held for reading time so a burst can't overrun.

Two VoiceOver behaviors shaped this: **assertive regions chime** (system alert sound on `aria-live="assertive"`, with or without `role="alert"`), and **an unchanged region is silent** with no way to force re-announcement. So:
- Editor character echo is **native** (#1248): the hidden `keyboard-input` textarea mirrors source + selection; echo-bearing keystrokes skip `preventDefault`, so the browser's own field edit is what the screen reader echoes — immediate, chime-free, correctly interrupting. Keydown still applies the model edit; `skipNextInput` prevents double application; mirror resyncs on every model change (suspended during IME composition).
- The `type` announcement kind remains for echoes that can't route natively (tab insert, single-char node deletions), paced.
- **The mirror is a unit conversion**: `Source` counts *graphemes* (`tokenPositions` from `UnicodeString`); `setSelectionRange` counts UTF-16 code units. `syncMirror` converts via `UnicodeString.getCodeUnitPosition` — raw position put the caret inside a surrogate pair after any emoji (#1329). Mirror is one-way; edits derive from `event.data`, `input.value`, or clipboard.

**So every recurring announcement must vary its text, or it is heard once and then sounds broken.** This is the single easiest mistake here. Ask what changes between two consecutive firings; if the answer is "nothing," the announcement is silent from the second firing. Summaries are constant by construction:

| Announcement | Constant form (silent after one) | What varies |
| --- | --- | --- |
| Stage output value | "Face" every evaluation | property that changed — "eyesOpen true" ([describeChange.ts](src/values/describeChange.ts)) |
| Output moved | "moved, cat moved left" per keypress | destination — "…to −2m 0m" ([direction.ts](src/components/output/direction.ts)) |
| Many outputs changed | "12 outputs changed in my grid" per tick | one example — "…, like 5" ([OutputDescriptions.ts](src/components/output/OutputDescriptions.ts)) |

Numbers round to tenths (imperceptible precision doesn't count as varying). Silence is the signal for no change. Cover with a test that fires twice over different state and asserts the strings differ.

**Snapping compares siblings in one frame, and every constraint has to be audible.** Moving output on stage snaps to grid and to siblings' edges, centres, baselines (#117, [snap.ts](src/components/output/snap.ts)). Load-bearing:
- Candidates are siblings under the same parent, compared in that parent's local coordinates — the frame `place` is written in (`Place.offset` composes `y` by *subtraction*).
- Scene comes from laying the stage out on demand, never from `Animator.scene` (empty when needed: animator is suspended while paused, and paused is the only editable state).
- A baseline comes from `getLayout`'s `ascent`/`descent` and the `line-height` `PhraseView` paints, never `FaceMetrics` (which carries only x-height ÷ cap-height); pairs only with another baseline.
- An axis the parent arrangement overrides (`Row` computes x, `Stack` y, `Grid` both) is never snapped or announced.
- Snap announcement carries target's name *and* coordinate ("aligned left" alone would be heard once).

**Exactly one describer speaks per change.** Output has two: `OutputView` summarizes value and deltas; `StageView` says what entered/changed/moved ([OutputDescriptions.ts](src/components/output/OutputDescriptions.ts)). When a value renders as a stage, `StageView` owns it and `OutputView.describeValue()` bails — same as for `Say` (voiced by speech synthesis). Both gated on `playing || stepping` — a paused stage is a preview being read with caret/echo announcements.

**Every announcement kind has a priority lane**, registered in [announcerQueue.ts](src/components/project/announcerQueue.ts). Adding a kind means adding to the registry and choosing a lane — an unregistered kind is a compile error. Mark a kind `immediate` when it answers a keystroke:

| Lane | Semantics | For |
| --- | --- | --- |
| `echo` | immediate, no dedupe — two of the same key are two events | per-keystroke character echo (`type`, `keyinput`) |
| `interrupt` | presents immediately, clears coalesced state, re-presents identical text; queued/echo preserved | failures: rejected edits (`ignored`), app errors (`banner`) |
| `queued` | FIFO, never dropped, reading-time paced, consecutive-dup dedupe | discrete action results (`fold`, `selection`, `tutorial-dialog`, …) |
| `coalesce` | one latest-wins slot per kind; `caret` is immediate, the rest paced | continuous streams (`caret`, `value`, `color`, stage/drag updates) |

Drain priority: interrupt → echo → queued → coalesce. Queued-before-coalesce guarantees a continuous stream can't starve discrete feedback.

To announce from any component:

```ts
import { getAnnouncer } from '@components/project/Contexts';
// ...
const announce = getAnnouncer();
if (announce && $announce) {
    $announce('fold', $locales.getLanguages()[0], message);
}
```

**Every editor command must be audible.** Silence is indistinguishable from a broken app. Caret/edit commands are covered by caret and echo announcements; every other command declares a `feedback` ([Commands.ts](src/components/editor/commands/Commands.ts), [feedback.ts](src/components/editor/commands/feedback.ts)) — either a localized confirmation, or one of `'caret'`/`'echo'`/`'focus'`/`'delegated'` naming what speaks. No way to declare silence, no way to pass a raw string. `Commands.test.ts` fails any command declaring nothing and enumerates `'focus'`/`'delegated'` claims for review. All three dispatch paths announce (editor keydown, ProjectView window handler, CommandButton).

**A cue is a sound, not a sentence, and it names the stream that caused a re-evaluation.** Audible evaluation cues (#537, [src/output/Cues/](src/output/Cues/)) are deliberately not announcements — a constant "re-evaluated" is heard exactly once (see the varying-text rule), and speech is too slow. Invariants:
- Sound table is total over `StreamKind` (a `StreamValue`'s discriminant, since `instanceof` can't separate family classes and definition names are locale data) — a new stream is a type error until it has a sound.
- Cues connect to the audio destination bypassing the music master (never ducked, never scaled, never squashed by the mix limiter). Timbres stay off the 12-TET grid so a cue is never mistaken for a note.
- Each kind has a floor (minimum spacing); overflow is *dropped, never queued* — a cue arriving after the event it names describes the past.
- `EvaluationCues.svelte` mounted only by `ProjectView` (not `PlayView`, which the landing showcase and tutorial also use). Fires in play + stepping across inputs in debug, never in edit. Off by default per device.

**A physics contact is cued whether or not the program is watching for one.** Cueing only re-evaluations meant a stage full of bouncing output was silent unless the creator wrote `Collision()`. `drainCollisions` reports to [contacts.ts](src/output/Cues/contacts.ts), a listener registry keyed by evaluator (so a docs page's previews don't cue a creator's project), holding neither `@db` nor Web Audio (Physics stays Node-testable). Rules:
- Strength comes from `manifold.contactImpulse` **inside the `contactPair` callback that is already open** — velocities readable after the step have already been changed by the collision.
- Only `starting` contacts cue (Rapier fires begin *and* end), above a strength threshold (a resting body's support impulse is nonzero).
- Normalizing constant is measured, not derived (3000, 95th percentile of Hiragana landing).
- `collision` is the one **polyphonic** cue — loudest four of a burst sound together at varied pitch and gain. Reaction path skips kind `collision` entirely (contact is the event, reaction is its consequence).
- Cue bus carries its own limiter (polyphony makes its sum unbounded).

**An animation is cued from what its poses do, and the mapping is deterministic so that repetition is audible.** A resting `Sequence` drives one long-lived Web Animation and never re-enters the evaluator — the Christmas tree had nothing for any cue to name. `OutputAnimation.start()` reports each tween to [figure.ts](src/output/Cues/figure.ts): rotation bends pitch, `offset.x` pans, `offset.y`/`scale` move pitch, `opacity` scales gain (so `fadeout` ends silent), color opens tone. Rules:
- `start()` is the seam because `retarget()` bypasses it — the optimization that stopped rebuilding a WAAPI animation every frame is what keeps a physics stage from cueing animations on top of contacts.
- First transition is never cued — it's where the animation starts, not somewhere it arrives.
- Each output's base pitch is a hash of its name — identical inputs give an identical figure (a loop heard as a phrase, `figure.test.ts` asserts).
- A pose that changes nothing is silent.
- A figure is scheduled a whole iteration ahead on the audio clock, so pause/cancel must take back what hasn't sounded (`soundFigure`'s handle + `cancelAnimation`).

**Each source has its own switch, and none is a master.** `gateOf` ([cues.ts](src/output/Cues/cues.ts)) is total over `CueEvent` and sorts every cue into `evaluation`/`contact`/`animation`; three settings rows govern independently — a row that means anything other than its label reads as broken. Split follows what the sources actually *are*: contact is not a re-evaluation, animation is continuous, rates differ by an order of magnitude. Only contact schedules kind `collision`.

**`StreamKind`'s other job: an input is only replayed into the same kind of stream that recorded it.** `Evaluator.mirror` replays each recorded input into whatever stream its `Path` resolves to in the revised program — a `Path` is `{type, index}[]` and can't tell two `Evaluate`s apart. Typing a new stream above an existing one shifts indices, and inputs arrive at wrong streams (a `Key` handed to `Speech` reached `text.normalize()` on an object and threw). Each input records its stream's `kind`; a mismatch stops the replay ([replayKind.test.ts](src/runtime/replayKind.test.ts)).

Announcement text is **primary-locale-only** — use `getPrimaryPlainText`, matching the region's `lang`. `aria-label` on a focused element is still appropriate for focus-time labeling; use Announcer for change-time announcements.

### Testing

**What each level costs, measured.** Default vitest (`fast` + `isolated`) is 504 files / 8,673 cases in ~15s; 440 files finish under 200ms — an ordinary unit test is free. A Playwright test costs ~5s on CI (1,472 test-seconds over ~275 tests across three shards); almost none is the assertion — navigation and hydration are 3–4s before anything is checked. That's a **~170× ratio**, and it is the whole argument for where a test goes. Cheapest of all: [page-preview.spec.ts](tests/end2end/page-preview.spec.ts) gets 8 tests in 1.4s by `fetch`ing the hosting emulator.

**Put a test at the cheapest level that would have caught the bug.** Parser, analyzer, evaluator, `src/edit/**`, locale tooling are pure and testable in milliseconds. Reach for a browser only when the claim is *about* the browser: hydration, focus order, live region reaching a screen reader, computed color, CSS geometry/writing mode, IME, clipboard, animation timing, Firestore round-trip through the real client. Cheaper than any of it: a **convention test** ([testIsolationConvention](src/util/testIsolationConvention.test.ts), [Commands.test.ts](src/components/editor/commands/Commands.test.ts), [logicalCssSync](src/util/logicalCssSync.test.ts), [ariaLiveConvention](src/util/ariaLiveConvention.test.ts)) — closes a whole class rather than one case.

**Adding an e2e test.** Each is worth 3–5 seconds a test forever. *Add an assertion to a spec already in the state you need*, before adding a `test()` — a new test is a new page load. The axe specs navigate once and check both color schemes on one page (`expectNoAxeViolationsInBothSchemes`). *Use the worker-scoped fixture* in [playwright/fixtures.ts](playwright/fixtures.ts), which signs in once per worker; `loginNewContext` is for tests that need a second identity. *Never `page.waitForTimeout`* — a web-first assertion or `expect.poll` is faster and clearer. *A new route is one line in `PUBLIC_ROUTES`*, not a new spec. Check `reportSlowTests` (names anything over 20s); the CI gate is the slowest of three shards.

**Adding a unit test.** Default to `src/**/*.test.ts` in the `fast` project. A file calling `vi.mock` must be listed in [isolatedTests.ts](src/util/isolatedTests.ts) or its mock leaks to every later file in the same worker. Vitest parallelizes by file and runs a file's tests sequentially in one worker: a `test.each` over thousands of corpus cases pins one lane. Prefer `test.each` to a loop inside one `test()`. If a test's cost scales with `static/examples/**` or `static/locales/**` rather than code under test, it is a **sweep**: mark it `@sweep <corpus root> <reason>`, list it in [sweepTests.ts](src/util/sweepTests.ts) ([sweepConvention.test.ts](src/util/sweepConvention.test.ts) enforces). Sweeps don't run in `npm run test:run`; pre-commit runs it for the corpus you staged; the `sweep` CI job runs it whole.

**When to run what.** Full suites are a gate, not a feedback loop.

| Moment | Run | Why |
| --- | --- | --- |
| While iterating | `npx vitest run <path>` on the file you're editing | Sub-second. `npm test` is watch mode and never exits. |
| Before declaring a change done | `npm run check:now` and `npm run test:run` | ~15s and ~70s. Rule 5 below. Add `test:sweep` only if you touched `static/examples/**`, `static/locales/**`, `src/util/verify-locales/**`, or `src/examples/**`. |
| Iterating on one e2e surface | `npx playwright test <spec>` or `npm run end2end:quick` when `build/` is current | Full suite is a ~5-minute three-shard CI gate. `end2end:failed` re-runs only failures. |
| Before committing a user-visible change | `npm run end2end` once, clean | Not repeatedly mid-session. `end2end:reuse` skips reseed against a long-lived `npm run emu`; accumulated emulator state makes both suites flaky. |
| Accessibility work | `npm run build && npx firebase emulators:exec "npx playwright test accessibility keyboard-navigation aria-snapshots announcer --project=chromium" --project=demo-wordplay --log-verbosity QUIET` | The one e2e subset worth running whole. |

Locally, Playwright runs four workers (`PLAYWRIGHT_WORKERS` overrides): the shared resource is the single-process Firestore emulator. If a run goes flaky, lower it before suspecting the change.

### Behavior

1. Don't assume. Don't hide confusion. Surface tradeoffs.
2. Minimum code that solves the problem. Nothing speculative.
3. Touch only what you must. Clean up only your own mess.
4. Define success criteria. Loop until verified.
5. After every code change, run `npm run check:now` and `npm run test:run` — **not** `npm test`, which is watch mode. Both must pass before declaring a change done: IDE diagnostics aren't a substitute for a clean full type-check, and unit tests catch regressions hand-testing misses (JSDOM and the locale verifier's tsx runtime differ from the browser). What a change owes beyond those two is in **Testing** above.
6. Always resolve all TypeScript errors, and never use `as`.
7. When you finish a user-visible change (anything touching `src/components/**`, `src/routes/**`, `src/output/**`, or a new built-in feature/dialog/output type), ask once at the end: "Want me to draft a CHANGELOG entry via `/changelog`?" Skip for refactors, test/doc/comment edits, and dependency bumps. Never invoke `/changelog` without confirmation. Two rules govern what an entry may be, both because **every entry is machine translated into 29 languages**: it is **one sentence** (a second only when the first would be untrue without it), and it describes **only what a creator can see** — the test is "could a teacher or a student notice this without reading the code?" (excludes refactors, internal architecture, CI/tooling, imperceptible perf, and a11y plumbing that changes no behavior). Editing a published entry buys 29 new translations, so fix a wrong one freely and never reword for style.

### Comments

When writing comments, focus on rationale for a behavior, but keep it to 1–2 sentences.
